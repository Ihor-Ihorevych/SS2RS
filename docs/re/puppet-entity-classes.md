## Summary

`CPuppetEntity` (data name `SPuppetEntity`, parent `CBaseEntity`/`SBaseEntity`) is the base of every character: it owns the **health, armour and alive flag**, the **movement command** (desired velocity and look, goal point, patrol) that the brain writes and the movement model executes, the **16-state puppet state machine**, the **model and mechanism** (physics body), the **rides** (seats, riders), the **character tools** (weapons and objects held), the **carried object**, the **attacks** that the parameter file describes (shooting processes, melee blasts, leaps), **spawning, death and the corpse**, and the **net hooks**. It has **519 named methods** (783 for the family; the table is [`puppet-entity-methods.md`](puppet-entity-methods.md)), **394 virtual slots** (102 from `CBaseEntity`, of which 55 are overridden here; 292 new) and **245 declared members**, of which the data stores 242 (55 replicated).

Four things to know first:

1. **The puppet does not decide; the brain does.** The brain (`brain-classes.md`) writes desired velocity, look direction, goal point and attack orders into the puppet; the puppet executes them every step (section 5). A puppet without brain stands still; the player's puppet gets its orders from `CPlayerBrainEntity` through the same members (`ProcessOperatorInput`).
2. **Everything numeric comes from the parameter file** (`en_pppPuppetParams`, `SPuppetParams`, 18 members of 7 records); the entity only adds instance overrides (`ep_`/`en_` values for step heights, fall height, flocking, sight and sense range, field of view).
3. **Co-op scales enemies by two rules**: they take less damage when the session sets extra enemy strength or has more players (section 7, with numbers), and `GetNominalHealth` is scaled for scoring (unresolved formula).
4. **The corpse** waits `GetCorpseStadyPeriod` seconds (the death parameters' value unless it is -1, then the global value; 1.0 s default), sinks and is deleted (section 8).

## Layout / rules

### 1. Parents and the virtual interface

`CPuppetEntity` ← `CBaseEntity` (data: `SPuppetEntity` ← `SBaseEntity`). Properties class `CPuppetProperties` (`SPuppetProperties` ← `SBaseProperties`, 40 members, 45 worlds; section 9). Parameter class `CPuppetParams` (`SPuppetParams` ← `CEntityParams`, 18 members). The **55 overridden slots** of the base entity are the life cycle (`OnCreate`, `OnUpdate`, `OnDelete`, `OnBoot`, `OnShutDown`, `OnStep`, `OnSpawn`), the collision (`OnHullTouched`), placement and velocity (`SetAbsPlacement`, `GetAbsPlacement`, `GetVelocity`, `SetVelocity`, `GetAngVelocity`, `SetAngVelocity`, `Teleport`), the net hooks (`GetNetBehavior`, `GetUpdatePriority`, `GetRelevantDistance`, `PreSendUpdate`, `PostReceiveUpdate`), the bounding boxes and view (`GetBoundingBox`, `GetBoundingBoxForAutoAiming`, `GetViewOrigin`, `GetViewTarget`, `GetHealthColor`), the aspects and renderable (`GetAspectForAttaching`, `GetAllAspects`, `GetModelRenderable`, `GetMechanism`), targeting (`IsAimable`, `IsAutoAimable`, `GetThreatSoundOrigin`), damage (`OnReceiveDamage`, `OnKicked`, `ExecuteDestruction`, `IsDestroyed`, the piercing-projectile trio), use by the player (`GetObjectManipulationFlags`, `GetObjectManipulationMessage`, `EnableUsage`, `DisableUsage`), the spawner link (`SetSpawner`, `YouWillBeMySpawnSource`), the script function `macIsAlive`, `PrepareForLaunch`, `UpdateTemps` and `AddDebugEntites` (some of these names are read from the slots that were not shared stubs; **medium**). The **292 new slots** are the puppet interface; they are the methods marked virtual in [`puppet-entity-methods.md`](puppet-entity-methods.md) by the exported attribute (the exported decoration says public virtual or not; not repeated per row).

### 2. How a puppet is made and parameters are loaded

`OnCreate` (7 KB of code, the largest function of the class) builds the puppet from its placed properties: it loads the parameter file (`puppet-classes.md` section 3.2), copies the instance values, creates the model and mechanism (`SetupAspects`, `SetCurrentMechanism`), makes sound sources for the three scheme sounds `Moving`, `NotMoving` and `Diving`, and warns `Puppet at coordinates ... uses local resource. That will not work in network.` when a resource is local. `OnBoot` starts it (alive effects and sound, attachments, spawner bookkeeping, the first state, and `CreateBrain`: `brain-classes.md` section 2.3). `OnShutDown` and `OnDelete` tear it down (children, tools, riders, brain).

### 4. State machine (`PuppetState`, `en_psState`; **medium**)

16 states (the list is in `puppet-classes.md` section 3.3). `SetState` (read in full) first calls a virtual hook (the "leave state" call), then runs the **exit hook** of the old state (one per state for 4 `PS_LOCAL_MOVE`, 5 `PS_GENERIC_ACTION_PLAY_ANIM`, 6 `PS_CONSECUTIVE_GENERIC_SHOOTING` and 7 `PS_GENERIC_MELEE_ATTACK`), stores the new state and runs its **entry hook** (4, 5, 6, 7 again) and installs the **think routine** (a named method that the step calls each step) by name: 4 -> `BeforeLocalMove`, 5 -> `GenericActionPlayAnim`, 6 -> `PrepareForCGS`, 7 -> `GenericMeleeAttackState`, 8 -> `ExplodeState`, 9 -> `FadeOut`, 10 -> `PrepareForAutoPatroling`, 11 -> `AutoFixingRideState`; state 12 calls `DoSpawnSource` instead; states 0 `PS_NONE`, 1 `PS_DEFAULT`, 2 `PS_IDLE`, 3 `PS_SHUT_DOWN`, 13, 14 and 15 install no routine here (the functions that start them do: `Disappear`/`Appear`, `SetSpawner`; **medium**, the read is of one function and the 4/5/9/10 assignment is from the order of the strings it names). The think routines chain: `BeforeLocalMove` -> `DuringLocalMove` -> `AfterLocalMove` -> `AfterLocalMoveFinished`; `PrepareForCGS` -> `WaitStartAttackDistance` -> `AdjustPoseForCGS` -> `WaitBeforeCGS` -> `PlayPreparingAnimForCGS` -> ... -> `OnCGSFinished` -> `OnAfterShootingDelayFinished` -> `OnPuppetRotationFinished`; `PrepareForAutoPatroling` -> `StartAutoPatroling` (names each routine's profile mentions). The legged kind adds a second small state (`LeggedPuppetState`: knock-out, ride sequence, leap; `puppet-legged-classes.md`).

### 5. The step (`OnStep`, 3 KB; outline, **medium**)

Every simulation step a puppet runs, in this order (the profiler scope names of the binary are in quotes): skip rendering work while `ren_bNoPuppets`; `"debug_info"` when the debug display is on; update tools (`UpdateTools`, `HandleToolsActions`), the carried object (`HandleObjectCarrying`), flocking (`DoFlocking`), the feelers (`ProcessFeelers`/`CheckEngageFeelers`), the ride-rider relations (`ProcessRideRiderRelations`), the health bar (`AddHealthBar` for a mini-boss), the idle notification and AI-enabled script events when `PLF_NOTIFY_IDLE`/`PLF_NOTIFY_AI_ENABLED` are set; `"mech_evalanim"` (evaluate the model animation on the mechanism when `ShouldEvaluateAnimation`); `"sound_handling"` (the moving and not-moving sounds when `PLF_USES_MOVING_SOUNDS`, with a volume that follows `GetPuppetMovingSoundRatio`); `"eval_animevents"` (the animation events of the current animation queue); `"lerp_vel&look"` (the movement step `LerpToDesiredVelocityAndLook` of the movement model, unless the puppet is placed by a placement entity: then `LerpIntoPlacementEntity`); then, for a rider, copies the ride's relations; in state `PS_AUTO_FIXING_RIDE` a tilt check against the two global ride-fix angles; and finally `Character in infinity detected!` when the placement stops being finite. The order is **medium** (one reading of an outline). **Corrected by T01-144** (the step was read in full): the ride-rider relations and the carried object come **early and in the middle**, and the tools (`HandleToolsActions` then `UpdateTools`) come **last**, after the rider animations and the auto-fix test; the auto-fix test compares the **doubled** pitch and bank with the two limits ([`puppet-carry-rides.md`](puppet-carry-rides.md) 9, 6).

### 6. Net behaviour and replication (**medium**; cross-checked against `replication.md`)

- `GetNetBehavior` (read in full): **`NEB_DYNAMIC` (2)** when the puppet has no spawner handle and is not a multi-spawner template, **`NEB_STATIC` (1)** otherwise (`replication.md` section 3.1).
- `GetUpdatePriority` (read): **8.0 while `en_bAlive` is set, 2.0 otherwise** (`replication.md` 3.5).
- `GetRelevantDistance` (read): the effective cull distance of the model when there is one; **0** without a model; on the host a model carrying one renderable flag also gets 0 (the flag was not resolved).
- **55 of the 245 members are replicated** (list in the table: `*`). They are exactly the state a client needs to show and predict a puppet: parameters and behavior link, alignment, health, armour and maximum health, alive flag, the move type and abilities and all the speed multipliers, the goal point group, the placement members (`en_qvOriginalPlacement`, `en_vNetPosition`, `en_vNetMechVelocity`, `en_fNetHeading`, `en_idCurrentMechanism`), the look target, the ride and seat members, the carried object, the desired tools and their immediate flags, both ammunition counts, the death damage type and place, the placement entity, the stretch and the net flags. **Everything about the brain, the attack execution, the feelers, the sound sources and the touch data is not replicated**: a client never runs the AI. `PreSendUpdate` and `PostReceiveUpdate` prepare the velocity and re-attach the puppet to its ride (`ShouldSyncVelocity` decides when the velocity is sent: for a non-predicted puppet that did not just arrive).
- **Remote calls** (`replication.md` 3.4): `DoStartPatroling`, `DoStopPatroling`, `DoGenericAnimation`, `DoGenericShooting`, `DoGenericMeleeAttack`, `DoGenericLeapOntoFoe` (legged), `DoExplode`, `PlayAnimNetRemote`, `StopAnimNetRemote`, `PlayAnimWait_net`, `PlayEnteringIntoRideSequence`, `PlayExitingFromRideSequence`, `SetPlacementEntityRemote`, `StoreTool`, `ThrowTool` and the legged `DoKnockOut`: the host decides and the call runs on every machine. `SpawnProjectile` logs `SpawnProjectile executed on client!` if it ever runs on a client.
- `IsLocal` (read): true when the puppet's operator is the local player (client index equals the player's, or the host and the host's slot).

### 7. Damage rules (**medium**; the functions were read)

- **`OnReceiveDamage`** (host only; a client ignores it): ignored without parameters; a damage of 0 or less is not "positive" and skips the player checks. For positive damage: if a **player brain** controls the puppet, its **god cheat** cancels the damage and its **invulnerability** (or `IsInvulnerable`, or `IsInvulnerableAsRider` for a rider whose seat says non-players are invulnerable) marks the damage as blocked. **A blocked damage is cancelled unless it is exactly 2,147,483,647 and its type is neither `DMT_KILL_ALL_CHEAT` (22) nor `DMT_SERIOUS_BOMB` (23)**: the kill-all cheat and the Serious Bomb respect invulnerability, `DMT_KILLER` (24) and `DMT_ABYSS` (25) do not. A maximum damage never harms the **level's boss puppet** (`CWorldInfoEntity.en_henBoss`). If the hit landed on a **mechanism part that carries a shield tool** (`CShieldDescription`: `sd_idShieldTool`, `sd_idShieldPart`; 2 parameter files), the damage is subtracted from the tool's health instead and the tool is thrown away at 0; the puppet takes nothing. What follows (health and armour arithmetic, death, kick, score, the `Damaged` effect) was **not read** (T01-140).
- **`ReceivesDamageFrom(dealer, type)`** (read): no dealer: yes. A player-controlled puppet hit by a player-controlled dealer: **always in deathmatch, otherwise only when friendly fire is on** (`sgp_bFriendlyFire`). A dealer whose base-entity member (not resolved) equals this puppet's refuses the damage unless it is an explosion (`DMT_EXPLOSION`, 11). A puppet that is **good or semi-neutral** (and a player, which counts as 0) takes damage only from an **evil** dealer; an evil or neutral puppet takes it from anyone else.
- **`GetReceiveDamageMultiplier`** (read): only **in co-op and for an evil puppet**: `m = 1 / (1 + 0.01 x (P - 1) x sgp_iEnemyStrengthPerPlayer) x 1 / (1 + 0.01 x sgp_iExtraEnemyStrength)`, where P is the number of players (a world-info count) and the two settings are members of `CSamTestRunParams` (`replication.md`); 1 otherwise. With extra strength 50, 25 per player and 3 players: `1 / 1.5 x 1 / 1.5 = 0.444`. (Whether the multiplier is applied to the amount, to health, or to both is part of the unread rest of `OnReceiveDamage`; **medium** for the formula, **low** for the use.)
- **Health pickups** (`CanReceiveHealth`, `ReceiveHealth`, `CanReceiveArmor`, `ReceiveArmor`; read): on the host only (`netIsRemote` false). Health is clamped to `[0, maximum]`. **In deathmatch, unless forced, a pickup cannot raise health above half the maximum** (above the larger of the old health and `max/2`), and `CanReceiveHealth` answers yes only while health is below `max/2`; outside deathmatch always yes. Armour has the same rule.
- **`GetKillScore`** (read): the score of the parameter file (`mpp_slScore`, the member `.0` of `CMiscPupeptParams`), 0 without parameters. **`GetNominalHealth`** (read): the health of the parameter file (member `.1` of `SPuppetHealthParams`; 100 without a file), scaled by an unresolved game-info formula for an evil puppet in co-op.
- **Falling and material damage**: `CanReceiveFallingDamage`, `CanReceiveRangeDamage` answer yes, `HandleFallingDamage` is empty in the base class (the numbers belong to the legged kind or to the unread `OnHullTouched`); `en_bDisableFallingDamageOnNextTouch` skips it once.

### 8. Death and the corpse (**medium**)

`DoDying` (host; read in full): tells the world info, calls the **death spawner** (`CSpawnerEntity::DeathSpawn`, an entity placed to spawn something when this puppet dies), makes each rider leave or fall out, increments a level statistic when the puppet is evil, sends a script event, clears `en_bAlive`, records the death time and stops its sounds and effects. `DoExplode`/`ExplodeState` (read): for a puppet whose death parameters give an exploding damage, applies **`DMT_EXPLOSION` damage with the parameter file's exploding damage and radius** from the puppet and then continues (`SPuppetDeathParams.pdp_slExplodingDamage`, `enemies.md`). `DropDead` (script): kills with a direction (default when no argument). **`GetCorpseStadyPeriod`** (read): the corpse's steady period: the puppet's own death parameter (`CCorpseSinkConfig.csc_fCorpseSteadyPeriod`, used only when it is not -1), else the global value of `CGlobalGameParams` (default 1.0 s, `rsc-ctl.md`: the corpse stays 1.0 s, sinks after a 0.1 s delay over 0.45 s, `effects-pipeline.md`); `FadeOut` starts the sink effect and `StartCorpseSinking` sets the `ignoreall` collision category and deletes the puppet when done. The one parameter file with its own config (`pdp_pcscCorpseSinkConfig`, 1 of 126) has steady period 100,000 s (it never sinks).

### 9. Properties (`CPuppetProperties`, `SPuppetProperties`, 40 members, 45 worlds)

The placed record of a puppet. 29 of the 40 members have the same name as an entity member with `ep_` instead of `en_`; the 11 that do not are the obsolete id members `ep_idPuppetObsolete` and `ep_idBehaviorObsolete` (the data names them `ep_idPuppet` and `ep_idBehavior`), the spawner link `ep_hspSpawner`, the auto-patrol marker `ep_hepAutoPatrolMarker`, `ep_bIsSpawned`, `ep_maPatrolMovingAbilities`, the step overrides `ep_fStepUpOverride` and `ep_fStepDownOverride`, the tactic handles `ep_hepTacticEntity`/`ep_henTacticEntity` and the death spawner properties handle `ep_hepDeathSpawner`. The 7 members the data stores as numbers are `ep_hspSpawner` (`.10`), `ep_bMultiSpawnerTemplate` (`.20`), `ep_hepAutoPatrolMarker` (`.30`), `ep_ulAutoPatrolMarkerEntityID` (`.31`), `ep_bIsSpawned` (`.32`), `ep_bAutoPatrolMarkers` (`.33`) and `ep_tsDefaultThreatSensitivity` (`.34`). The class has 9 named methods: spawner-link breaking (`BreakSpawnerLinks`, `BreakMultiSpawnerLinks`), the multi-spawner test, `MarkAsSpawnee` (sets `ep_bIsSpawned`), the editor bounding box, preview renderable and effective entity, `GetSpawneeCountLimitType` and the editor command `GetExecutionCommand_EDT`. `OnUpdate` of the entity copies a changed properties record into the entity (the death spawner is refused for a multi-spawner template with the warning `Multispawner template can't be used as death spawner!`).
