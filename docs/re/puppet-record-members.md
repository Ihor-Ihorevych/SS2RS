## Summary

A puppet parameter file (`.ep`, 126 files under `Databases/Puppets` and the player's) is one `SPuppetParams` object (or a subclass) made of **records**: health, body, death, effects, miscellaneous, and for the walking kind three environments and a knock-out record. The data stores most members under their declared name and **25 members under a bare number** (`.1`, `.2`, ...). **The DLL declares a name for every one of them**: the static member table of each record class lists all members in declaration order with the original identifiers (`php_` health, `pbp_` body, `pdp_` death, `pfx_` effects, `mpp_` misc, `pep_` environment, `kop_` knock-out). The earlier statement that "no declared table exists" for these records (`puppet-classes.md`, first version) was wrong: the tables exist and were not matched.

1. **Names.** The data's member order equals the declared order in **all** records of the install (126 health, body, death, effect and misc records; 258 environment records; 86 knock-out records), every named data member sits at the declared name's position, and the stored types fit the declared types (script, section 2). So each number is the name at its position (table in section 2).
2. **Health.** `.1` is **`php_slMaxHealth`** (the puppet's start health and its maximum), `.2` is **`php_slMaxArmor`**, `.3` is **`php_ghFallingHitDamage`** (a graph, stored in 29 files only). The three healing members are a **regeneration rule** with a start threshold, an end threshold and a rate in health points per second (section 3.2: the boss data now has a precise meaning).
3. **Body.** `.10` `pbp_strModel`, `.1` `pbp_fStretch`, `.3` `pbp_vViewOrigin`, `.4` `pbp_qvShootOrigin`, `.11` `pbp_vViewOriginSitting`, `.12` `pbp_qvShootOriginSitting`, **`.7` `pbp_vViewTarget` and `.6` `pbp_vShootTarget`** (the order in the file is `.7` before `.6`): this closes the open question of `brain-line-of-sight.md` about which target vector is which.
4. **Death.** `.1` `pdp_bExplodes`, `.2` `pdp_fExplosionDamage`, `.3` `pdp_fExplosionFallOff`, `.4` `pdp_fExplosionHotSpot`. **114 of the 126 files explode**; the explosion fires when the health reaches 0 and the damage taken since the last reset reaches `pdp_slExplodingDamage` (0 in 91 of the 114 exploding files: always).
5. **Effects.** `.1` `pfx_ulStepEffectPlatforms` and `.2` `pfx_ulStepSoundPlatforms` are **platform masks** (bit 0 PC, bit 1 Xbox); all 126 files store `0xFFFFFFFD` (every platform but the Xbox), which is also the class default.
6. **Misc.** `.8` `mpp_esEnemySize` (stored in 23 files; the class default is 1).
7. **Environment.** `.1` `pep_fAcceleration`, `.2` `pep_fDecceleration`, `.3` `pep_fSpeedMin`, `.4` `pep_fSpeedMax`, **`.7` `pep_fWalkVelocity`**, `.5` `pep_fMovingRotationMin`, `.6` `pep_fMovingRotationMax`, then the two named standing-rotation members. The acceleration and deceleration set the **force of the motion joint per unit of mass**, the speed pair is the per-puppet speed range (`GetInstanceMoveSpeed(en_fRnd)`), the walk velocity is the **walk / run threshold of the animation chooser**, the rotation pairs are the **turn rates** (section 8). This answers T01-214 for the roles of the members and for the one caller of `GetInstanceMoveSpeed`.

## Layout / rules

### 1. How a record is read (**high**)

Each record class has **one table of members in declaration order**. The data stores the members in this order; a member that the data's type table does not name is written with its **number** (the number is an identifier of the member inside the class, not its position: for example the body record stores `.10, <named>, .1, <named>, .3, .4, <named>, .11, .12, .7, .6, ...`). A declared member that a file does not store keeps the **class default** (the constructor's value): this happens for the last health member (`php_ghFallingHitDamage`, 97 of 126 files) and the last misc member (`mpp_esEnemySize`, 103 of 126 files). The script confirms the order for every record of the install and that no number is ambiguous.

### 2. The numbered members (**high**: position, count and type agree everywhere)

### 3. `SPuppetHealthParams` (**medium** unless marked)

**3.1 Health and armour.**

- **`php_slMaxHealth` (`.1`)** is the puppet's **nominal health**: `GetNominalHealth` returns it (100 when the puppet has no parameter file), and for an evil puppet in a game session the game-info entity rescales it (the formula was not resolved: T01-140 and T01-162). `GetInitialMaxHealth` is the same function. **At boot (`OnBoot`) the puppet's maximum health and its health are both set to the nominal health** (a respawn through the reset of dynamic members sets health to the stored maximum and armour to 0). The value is also the **base of the healing thresholds** (3.2). Data: 126 files, 10 to 1,000,000; the player's file has 100.
- **`php_slMaxArmor` (`.2`)**: no reader of the file's value was found in the puppet classes read (the start of a puppet sets armour 0 and leaves the armour maximum to the code that creates the player); the data stores 0 in 121 files, 100 (equal to the health) in 4 and 999,999 in 1 (the file whose health is 999,999 too). **Low** for the use; the name is the only evidence (T01-380).

**3.2 Healing over time (`ApplyHealing`, **medium-high**: the function and the thresholds were read in full and the threshold arithmetic checked in the instruction listing).** The members `php_slHealingStart`, `php_slHealingEnd` and `php_slHealingPerSec` define a **regeneration rule** that every puppet evaluates once per simulation step in its step routine (the `auto_healing` profile scope):

1. **Thresholds.** `GetHealingInfo` returns three integers: the rate `p = php_slHealingPerSec` **unchanged**, and the thresholds `S = trunc(php_slHealingStart x r)` and `E = trunc(php_slHealingEnd x r)`, where **`r` = the puppet's nominal health divided by `php_slMaxHealth`** (the file's value; `r` = 1 unless the nominal health was rescaled). Truncation is toward zero. Without a parameter file the rate is -1 (never heals).
2. **When it is switched off.** If the puppet flag **`PNF_DISALLOW_RECHAGING`** (8, member `en_pfFlags`) is set the step only clears the healing state `en_bHealing` and does nothing else. The boss scripts set this flag (`macAllowRecharging`, `bosses.md`).
3. **Start.** While not healing: when **`p > 0` and the current health is below `S`** (strictly less), healing starts: `en_bHealing` := 1, the healing clock `en_tmLastHeal` := now, and the macro event **`HealingStarted`** is sent to the puppet's script object.
4. **While healing, every step.** Let `t` be the seconds since `en_tmLastHeal` (the clock counts 2^32 ticks per second) and `T = 1 / p` seconds. If **`t > T`**: `n = trunc(t / T)` points are healed, and `en_tmLastHeal` moves forward by exactly `n x T` (the remainder `t - n x T` is kept). If `n > 0` the healing is applied as a **damage record of amount `-n`** with the puppet itself as dealer, no direction (the same damage entry point as any hit, `OnReceiveDamage`; a negative amount leads to `ReceiveHealth(n)`: `puppet-entity-classes.md` section 7, so the health is clamped to the maximum and, **in a deathmatch session unless forced, to half of it**).
5. **Stop.** Only **after a heal tick**: if the health is now **`>= E`** healing stops (`en_bHealing` := 0) and the macro event **`HealingStopped`** is sent. A puppet whose health rises above `E` by other means keeps `en_bHealing` set until its next heal tick.
6. **Host.** The routine itself has no host test and the caller was not read for one; the damage entry point is host-side (`puppet-entity-classes.md` section 7), so a client presumably gains nothing from it (**low**).

Data (script): 15 files have a rate above 0, with 9 distinct `(start, end, per second)` triples: (30, 55, 10), (50, 100, 10), (70, 100, 10), (200, 0, 1), (200, 500, 1), (750, 1000, 100), (4999, 5000, 200), (5000, 10000, 1000), (5999, 5000, 100). So **Kleerofski** (4999, 5000, 200) starts healing as soon as his health is below 4,999 and heals 200 points per second until a tick leaves him at 5,000 or more: the regeneration after the first hit that `bosses.md` suspected. A triple whose `end` is not above `start` ((200, 0, 1) and (5999, 5000, 100) in the list; the script counts 5 such records) makes a **cycle**: healing starts below `start`, the first tick heals `n` points and stops (the health is already at or above `end`), and the next step starts again, so the puppet heals about `p` points per second while its health is below `start`, with a `HealingStopped` and a `HealingStarted` event pair at every tick and the clock remainder lost at every restart (the true rate is slightly below `p`).

**3.3 The health bar (`AddHealthBar`, **medium-low**).** For a puppet that carries the mini-boss flag the step creates a **health bar entity** attached to the puppet's model, placed in the puppet's own frame **above the top of the mechanism's bounding box by `php_fHealthBarOffsetY`** along the up axis (0 in 125 files, -8 in one, so a negative value lowers the bar). `php_fHealthBarSize` (2.0 in 125 files, 10 in one) and `php_fHealthBarCullingDistance` (1,000 in 125, 300 in one) are stored with the bar's parameters; the bar object that **reads** them was not traced (T01-380). The class default of the three is 2.0, 1,000, 0. The global textures of the bar (`ggp_ptxPuppetHealthBarEdge` and `Tile`) are in the global game parameters (`rsc-ctl.md`).

**3.4 `php_ghFallingHitDamage` (`.3`, **low**).** A graph holder (a value and a link to a graph). The class default and **all 29 stored records** hold the same **step-up graph with two control points: input 20 gives 0, input 60 gives 100** (script). Presumably damage as a function of the speed of a fall (name: "falling hit damage"). **No reader was found**: the direct calls of the engine's graph-holder reader in the game DLL are in the spawner, brain, flamer, auto-aim and puppet-render code and none takes this member; a call through the graph object's own virtual function was not searched, so a reader cannot be excluded. It may be a leftover (T01-380).

### 4. `SPuppetBodyParams` (**medium**; the vectors and the stretch are specified in `brain-line-of-sight.md`)

- **`pbp_strModel` (`.10`)**: a model file name. The **generic legged puppet** (`CGenericLeggedPuppetEntity::OnCreate`, read in full) converts a non-empty string into the model link `pbp_pmcModel` of its parameters and **clears the string**; all 126 files store an empty string, so the member is an authoring convenience. **Medium.**
- **`pbp_pmcModel`**: the model configuration; `GetPuppetModel` returns the puppet's own override if it has one, else this link (the player puppet has its own variant).
- **`pbp_fStretch` (`.1`)**: the model scale: `GetPuppetStretch` = this times the puppet's own stretch `en_fStretch` (`brain-line-of-sight.md` section 4); 0.5 to 30 in 30 distinct values.
- **`pbp_fDefaultAnimationLerpTime`** (read in `OnCreate`, **medium-high**): the puppet's default animation blend time `en_fAnimLerpTime` **starts at 0.2 s** and is replaced by this member **when it is 0 or more**; -1 (117 of 126 files) keeps 0.2 s. The member is the blend time the puppet passes to its animation player when a call gives none (the state-clear and clone calls take it).
- **`pbp_vViewOrigin` (`.3`), `pbp_vViewOriginSitting` (`.11`), `pbp_qvShootOrigin` (`.4`), `pbp_qvShootOriginSitting` (`.12`), `pbp_vViewTarget` (`.7`), `pbp_vShootTarget` (`.6`)**: the eye point (standing, and sitting in a ride), the shooting origin (with orientation; the puppet's shooting-origin attachment is used when `pbp_idAimOriginAttachment` names one) and the two look-at points. **New fact (part of `brain-line-of-sight.md` open question 2 and T01-363):** the data stores `.7` before `.6`, and the declaration lists the view target before the shoot target, so **`.7` is `pbp_vViewTarget` and `.6` is `pbp_vShootTarget`**. `GetViewTarget` agrees: for the request purpose with the value 1 it reads the shoot target, for every other purpose the view target; both are multiplied by the puppet's stretch as that page states. The unit of the vectors, the rotation and the other puppets' variants stay with T01-363.
- **`pbp_idAimOriginAttachment`**: the model attachment whose placement is the aim origin (`GetSightsPlacement`; `AimOrigin` or empty in the data).
- **`pbp_bBonesMoveHulls`** (105 of 126 are 0): `ShouldEvaluateAnimation` answers yes when the puppet has a mechanism and this flag is set: the model's animation is evaluated every step because **the bones drive the collision hulls** (the name's meaning; **medium**).
- **`pbp_bForcesPiercingProjectileToExplode`** (10 files set it) and **`pbp_fPiercingProjectileResilianceMultiplier`**: a piercing projectile (one that passes through targets) asks the target. `ForcesPiercingProjectileToExplode` returns the flag. **`GetPiercingProjectileResilience` = `trunc((armour + health) x multiplier)`**, the plain sum without a parameter file (**medium-high**, checked in the listing). The multiplier is 1.0 in 124 files and **1e6 and 1e8 in two files** (practically invulnerable to piercing).
- **`pbp_asdShields`**: shields, `puppet-tools.md` section 6. **`pbp_bAutoAimable`** (default 1; 0 in 7 files): `IsAutoAimable` is true only for an **evil** puppet (alignment 1) that is alive and passes one more virtual test, **and** whose file allows it (a puppet without a file is auto-aimable); the reader is the player's auto-aim (`hitscan-shot.md`).

### 5. `SPuppetDeathParams` (**medium**; `pdp_bDisableBulletDamageAccumulation`, `pdp_fStretchOverride` and the explosion step read in full)

**5.1 When a puppet explodes.** `OnReceiveDamage` keeps the **damage taken since the last reset** in `en_slAccuDamage` (0 after a respawn or a reset of the dynamic members) and the death routine `DoDying` repeats the test below:

- A positive hit adds its amount to `en_slAccuDamage`; **an amount of 2,147,483,647 (the "kill" amount) sets it to 1,000,000** instead. **Exception:** when **`pdp_bDisableBulletDamageAccumulation` is set** (7 files), hits of damage type **19 `DMT_BULLET`, 20 `DMT_SNIPER_BULLET` and 21 `DMT_SLUG`** are **not added** (so a hitscan weapon cannot make such a puppet explode; this is the "parameter flag" of `T01-364` and the three damage kinds 19 to 21 of `behavior-validity-terms.md`: **medium-high**, the three numbers and the flag are read from the same condition).
- When the health is **0 or less**, if **`pdp_bExplodes` is set**, the local flag **`PLF_EXPLODED`** (4) is clear and **`en_slAccuDamage >= pdp_slExplodingDamage`**, the puppet **explodes** (a virtual `Explode`: state `PS_EXPLODING`, below) instead of dying normally. Otherwise it dies normally (`DoDying`'s other steps). `pdp_slExplodingDamage` is 0 in 91 of the 114 exploding files, so those **always explode on death**; the other 23 have a threshold of 80 to 200 (80 once, 90 twice, 100 in 7, 120 in 6, 125 twice, 140 in 3, 200 twice) and explode only when that much damage accumulated. **The 7 files that set the bullet flag are 7 of these 23** (script): their hitscan damage never counts towards the threshold.

**5.2 The explosion (`ExplodeState`, `DoExplode`).** In state `PS_EXPLODING` (8) the puppet builds an **explosion damage descriptor** of damage type **11 `DMT_EXPLOSION`** with the amount **`pdp_fExplosionDamage`** (default 25; 0 in 94 of the 114 exploding files: a visual explosion only), the **force impulse `pdp_fExplosionForceImpulse`** (default 2,000: 2,000 in 33 files, 1,500 in 14, 1,000 in 5, 0 in 74), the **up ratio `pdp_fExplosionForceImpulseUpRatio`** (default 0.5), the **hot spot `pdp_fExplosionHotSpot`** (full damage inside it) and the **fall-off `pdp_fExplosionFallOff`** (the damage reaches 0 at this distance; defaults 5 and 10, in the game's distance unit) and hands it to the damage service with the puppet as origin and dealer, then continues with the next virtual step of the puppet (the host's `DoExplode`, a remote call that runs on every machine). `DoExplode` then throws the death tools, sets `PLF_EXPLODED`, plays the model's explosion scheme sound and effect (with the **sound range override of the effect record**, 6.2) and **destroys the puppet entity**. The exact signature of the damage-service call was not resolved (**medium-low**: the six numbers are exactly those listed; the unit of the impulse and of the distances is the game's).

**5.3 `pdp_fStretchOverride`** (read in `StartCorpseSinkingEffect`, **medium-high**): the **size of the corpse-sink effect** is by default **0.3077 (4/13) times the length of the diagonal of the mechanism's relative bounding box**; when this member is **not -1** (-1 in 119 files; 3.5 and four other values in 7) its value is used instead. `pdp_pcscCorpseSinkConfig`: the corpse timing, `puppet-entity-classes.md` section 8 and `rsc-ctl.md` (set in 1 file).

### 6. `SPuppetEffectParams` (**medium**)

**6.1 Platform masks (`.1`, `.2`).** `EPlatform` is a 32-bit **mask indexed by the platform number** (bit 0 PC, bit 1 Xbox: `bmf.md`, `gui.md`). In the legged `OnAnimEventStep` the step effect plays only when **bit `p` of `pfx_ulStepEffectPlatforms` is set, where `p` is the engine's emulated platform** (0 on the PC): the value `0xFFFFFFFD` (bit 1 clear) is stored by **all 126 files** and is the class default, so on the PC the effect always plays and the only effect of the member is to switch the Xbox build off. `pfx_ulStepSoundPlatforms` has the same type, default and data; **its reader was not found** (T01-380; presumably the step sound has the same test).

**6.2 Sound ranges.** Each pair is a **fall-off distance and a hot-spot distance** (full volume inside the hot spot, silence beyond the fall-off; `helper-classes-params.md` section 7 uses the same words). The six members default to **-1 = "use the global default"**. The global defaults are the two `CPuppetSoundRanges` records of `CGlobalGameParams` (`gpp_psr` for an **evil** puppet, `gpp_psrOther` for all others; alignment 1 is evil). At creation `OnCreate` takes the global pair and **overrides each distance with the file's value when it is 0 or more** (checked per distance: a file may set only one of the two); the three families are the **puppet sounds** (the puppet's own sound source: `pfx_fPuppetSounds...`), the **moving sounds** (the moving and not-moving loops) and the **step sounds** (the legged `OnAnimEventStep`: same rule at each step event). `DoExplode` uses the **puppet sounds pair** for the explosion's sound (there the file's value counts when it is not exactly -1). Data: the puppet sounds are overridden in 46 of 126 files (fall-off up to 2,000, hot spot up to 600), the moving sounds in 45, the step sounds in 31.

**6.3 Step effect size and alive effect.** `pfx_fStepEffectStretch` and `pfx_fStepEffectPower` (1 in 118 and 119 files, up to 500 and 10) are passed to the step effect that the puppet spawns at the animation event's attachment for the material under the foot (`samSpawnEffectForMaterial`; in water the world info's water-step effect is used). `pfx_fAliveEffectStretch` and `Power` (1 in 125 files, 3 in one) scale the **effect that a living puppet keeps** (`SpawnAlliveEffects` at creation, an effect scheme looked up by the model's name).

### 7. `CMiscPupeptParams` (**medium**)

- **`mpp_slScore`**: `GetKillScore` (`game-modes.md`). **`mpp_ptxRideIcon`**, **`mpp_ptxRideAmmoIcon`**, **`mpp_ptxBossIcon`**: the HUD elements `CVehicleSimpleHudElement`, `CVehicleAmmoSimpleHudElement` and `CBossSimpleHudElement` read them through `GetIconTextureOverride` (read, **medium**: each element replaces its icon with the puppet's when the member is set). **`mpp_strBossName`**: the translated boss name of the boss bar (`bosses.md`).
- **`mpp_fSniperDamageMultiplier`**: 1.0 in 114 files, 0.25, 0.5 or 0.75 in 12; by its name the **factor on damage that a sniper bullet does to the puppet**; the reader was not found (**low**; T01-380 and `hitscan-shot.md`).
- **`mpp_esEnemySize` (`.8`)**: the **enemy size class**, enumeration `EnemySize` (0 `ES_EX_SMALL` ... 5 `ES_BOSS`, `puppet-classes.md`), **stored in 23 files and class default 1 (`ES_SMALL`) for the other 103**. The spawner's multiplier code takes an enemy-size argument (`SetDelaysAndType`, `AdjustForLauncherAndFormationParams`, `CSpawnerTweakEnemySize`: `mechanism-classes-spawner-tweaks.md`); that the argument is this member is the natural reading but was not traced (**low**; T01-166 and T01-380).

### 8. `SPuppetEnvironmentParams` (`CLPEnvironmentParams`; **medium** per member, the three uses read in full)

The legged puppet picks the record by pose (`GetEnvironmentParams`: land, air for flying, water for diving and swimming: `puppet-legged-classes.md` section 3). Let `rnd` be the puppet's `en_fRnd`: **a uniform number in [0, 1) drawn by the puppet's constructor** (0 for the player; `behavior-mover-steering.md`), fixed for its life.

| Member | Meaning (declared name) | Evidence |
|---|---|---|
| `pep_fAcceleration` (`.1`) | **acceleration** (force per unit of mass; the game's length unit per second squared): when the puppet's mechanism is set, its linear motion joint gets the **acceleration force = body mass x this value** (`SetCurrentMechanism`); the step then refreshes the joint's force every step as the mass times this value times the puppet's acceleration multiplier `en_fAccelMultiplier` times further per-step factors (the air-control factor while air-controlling: the legged step, T01-141). `GetCurrentAcceleration` = one per-puppet factor x `en_fAccelMultiplier` x this. | `SetCurrentMechanism` and `GetCurrentAcceleration` read in full (**medium-high**) |
| `pep_fDecceleration` (`.2`) | **deceleration**: the joint's **break force = mass x this value** (same two functions; `GetCurrentDeceleration` = factor x `en_fDecelMultiplier` x this). | same |
| `pep_fSpeedMin`, `pep_fSpeedMax` (`.3`, `.4`) | the **range of the puppet's nominal speed**: **`GetDeclaredNominalVelocity` of the legged kind = `SpeedMin + (SpeedMax - SpeedMin) x rnd`** (`CLPEnvironmentParams::GetInstanceMoveSpeed(rnd)`, whose **only caller** is this function; 1.0 when the pose has no record). So identical puppets differ by `rnd` between the two numbers (8.5 to 9.5 for the Kleer). Speed units of the game per second (the same unit as the velocity members). | the two functions read in full (**high** for the formula: it is the same function the helper page read, plus its caller) |
| `pep_fWalkVelocity` (`.7`) | **the walk / run threshold of the moving-animation chooser**: `PrepareMovingAnimData` sets its speed class to 2 when the measured speed is 0, otherwise to "slow" when **speed < this value** and "fast" otherwise (`puppet-moving-anim.md`: the slow limit). | `PrepareMovingAnimData` read (**medium**) |
| `pep_fMovingRotationMin`, `Max` (`.5`, `.6`) | **turn rate, in degrees per second, while the puppet is pushing forward**: the step uses `(Max - Min) x rnd + Min`, converted to radians (x 0.017453292) and multiplied by the puppet's turning-velocity multiplier `en_fTurningVelocityMultiplier` and a per-step factor. **Branch:** when `en_bAddingThrust` is 0 the standing pair is used, else the moving pair. 3e38 in 4 records means "no limit". | the legged `LerpToDesiredVelocityAndLook` rotation limit part read (**medium**); the rest of that step is T01-141 |
| `pep_fStandingRotationMin`, `Max` | the same **while the puppet is not pushing forward** (turning on the spot; the player uses larger values). | same |

Defaults and data are in section 2. Test: the Kleer's land record with speed 8.5 to 9.5 and `rnd` 0.25 gives a nominal speed of 8.75.
