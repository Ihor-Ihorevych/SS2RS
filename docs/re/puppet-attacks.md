## Summary

An attack of a character is a **parameter record plus a timed chain of think routines**; the world is only touched at the animation events inside the chain.

- A **shooting process** (`CShootingProcess`, 123 records in 92 `.ep` files) is started by `DoGenericShooting(attack id, shot count)` and runs the **consecutive generic shooting (CGS)** chain in puppet state `PS_CONSECUTIVE_GENERIC_SHOOTING` (6): wait until the foe is close enough, stop and turn to the foe, wait, play a prepare animation, aim, then **`count` shots** (each plays a shoot animation), a leave animation, a wait, and back to `PS_DEFAULT` (section 4).
- The **bullet or projectile leaves at the animation event** `Shoot blast (<id>)` (129 events in the data), not at a timer: the event calls `OnAnimEventShootingBlast`, which asks the puppet's shooter to **aim at the foe and fire the named blast** (`CSingleBlast`, 168 records). The aim point, the miss offset, the prediction of the foe's motion, the scatter and the launch solution are in section 5.
- A **melee attack** (`CMeleeAttack`, 71 records) plays one animation; the animation event `Melee blast (<id>)` (36 events) runs **`OnAnimEventMeleeDamage`**: every entity with a collision hull within a sphere around the blast's attachment receives a damage record and a kick impulse (section 7). The run-over attack's blasts use the same function.
- A **projectile** is created on the host from a parameter file through `FireProjectileFrom`, `ThrowProjectileFrom` or the shooter's `FireProjectile`, always through `SpawnProjectile` (section 6).
- A **tool launch** (`LaunchTool`, throwing a held tool or object) solves a **free-fall trajectory at a fixed pitch** from the three graphs of a `CThrowDescription` (30 records in 15 files, all NPCs and two bosses) (section 8). Two small numeric solvers are shared by all of this (section 9).

## 3. Starting and ending an attack

**Remote calls.** `DoGenericShooting(attack id, shot count)` and `DoGenericMeleeAttack(attack id)` are remote calls (`puppet-entity-classes.md` section 6): on the host they are sent to every machine; on each machine the call stores the arguments and enters the state. For shooting: the attack to start := the id, the number of shots := the count, the shot index := 0, the order time := now, then **`SetState(PS_CONSECUTIVE_GENERIC_SHOOTING)`**. For melee: attack to start := the id, then `SetState(PS_GENERIC_MELEE_ATTACK)`. Callers of `DoGenericShooting` found by scanning: the brain's `CommandGenericShooting`, the puppet's `DoAttack` and two more (a behavior object's creation and one mis-named function); of `DoGenericMeleeAttack`: `CommandGenericMelee`, `DoAttack` and one behavior creation. The brain methods `CommandGenericShooting`/`CommandGenericMelee` are what the script functions `AttackShoot` (default id: the first shooting process of the file; default count 1) and `AttackMelee` call. **Medium.**

**State entry and exit.** `SetState` (`puppet-entity-classes.md` section 4) runs the entry hook `OnBeginCGS` on entering state 6 and the exit hook `OnEndCGS` on leaving it; likewise `OnBeginGenericMeleeAttack` / `OnEndGenericMeleeAttack` for state 7. The entry hook of state 6 clears a puppet flag and records the series start time (now). The melee entry hook clears bit value 4 of the puppet's execution abilities, the exit hook sets it again (the same bit is cleared by `AdjustPoseForCGS` when the process says "must stop to shoot" and set by `OnEndCGS`): while it is clear the puppet's brain is not given new orders (**medium-low**; the meaning of the bit was not resolved).

**`OnEndCGS`** (exit hook): if an animation is still played it is removed (with a zero lerp time); if the process has a character mover and the brain is in state `BS_DEFAULT_CHARACTER_MOVING` (2) the brain's `UnforceMovingType` is called (it undoes what `PrepareForCGS` did); the brain is told **`OnActionFinished`** (it then reconsiders its behaviour: `brain-classes.md` section 4); the current attack id is cleared, the added pitch is set to 0 and execution-ability bit 4 is set.

**Player and scripted entry (`DoAttack`, `StopAttack`).** `DoAttack(button, held)` acts only while the puppet is in `PS_IDLE` (2) or `PS_DEFAULT` (1): it turns the button into a `PlayerFire` value, searches the lists **in the order shooting processes, melee attacks, leap attacks, run-over attacks** for the first record whose `*_pfPlayerFire` equals it, and starts it: **shooting with the count 1, or 2,147,483,647 when `held` is set**, melee through `DoGenericMeleeAttack`, leap through `DoGenericLeapOntoFoe`; a run-over match starts nothing; at the end it marks the puppet non-idle. `StopAttack` in state 6 sets the shot count to 0 (the series ends after the shot in progress) and marks non-idle. The player's puppet overrides both (`CPlayerPuppetEntity`, not read: T01-264).

**May it fire.** `CanPerformGenericShooting`: **false while the state is already 6**; a rider (ride state `RS_RIDING` 3) whose seat refuses the own weapon gets false and the console text "Shooting is rejected for rider ... because seat ... on ride ... doesn't allow shooting" is stored on the brain; otherwise true. `CanFireFromOwnWeapons`: true without a ride; with a ride the seat is looked up by the puppet's seat id and the answer is **false only when the seat names no weapon of its own and does not have the seat flag `SF_RIDER_CAN_SHOOT_OWN_WEAPON` (1)**. `IsAllowedToFire` is that test for a riding puppet and true otherwise. `CanPerformMeleeAttack`: false only while the state is already 7. **Medium.**

## 4. The consecutive generic shooting chain

Notation: "think X after t" means the puppet's next-think call with the delay t seconds and the named routine (`main-loop.md`); "min delay" is 1e-5 s. The **process** is the shooting process whose id equals the current attack id; if it cannot be found, every routine of the chain prints "... Attack with ID ... can't be found in character ..." (the first prints "Shoot attack with ID"), tells the brain `OnActionFinished` and the puppet goes to `PS_DEFAULT`. Time is a 64-bit fixed point with 2^32 units per second (`main-loop.md`); "elapsed" below is the tick difference divided by 2^32. Animation lengths are `GetAnimationLength(anim, 1)`; the lerp time is the member `en_fAnimLerpTime`.

| # | Routine (state 6 unless said) | Rule |
|---|---|---|
| 0 | `DoGenericShooting` | the order (section 3). The think routine of state 6 is `PrepareForCGS`. |
| 1 | `PrepareForCGS` | current attack id := attack to start. Process missing: `PS_DEFAULT`. **If the process has a character mover (`sp_pmcCharacterMover`), the puppet has a brain, and the brain is in `BS_DEFAULT` (0) or `BS_CHARACTER_NOT_MOVING` (1): the brain's `ForceMovingType(mover, -1)` is called** (the mover is forced with no time limit; `MR_FORCED`). Then: if `sp_fStartAttackDistance` is above 0, think `WaitStartAttackDistance` after the min delay; otherwise call `AdjustPoseForCGS` at once. |
| 2 | `WaitStartAttackDistance` | no target entity (the puppet's look-target handle, `en_henLookTarget`; **medium-low** that this is the member): think `AdjustPoseForCGS` after the min delay. Otherwise if **elapsed since the order time is greater than `sp_fMaxWaitStartAttackPeriod`**: give up (brain `OnActionFinished`, `PS_DEFAULT`). Otherwise measure the **horizontal distance** (x and z of the two absolute placements) to the target: **below `sp_fStartAttackDistance`** -> think `AdjustPoseForCGS` after the min delay; else think `WaitStartAttackDistance` again **after 0.1 s**. |
| 3 | `AdjustPoseForCGS` | **If `sp_bMustStopToShoot`: `StopMoving` and execution-ability bit 4 cleared.** Then the **added pitch** is set (only when `sp_bAdjustPicthToThrow` is set and the process's **first blast has a projectile that is `PF_FALLING`**): with no pitch graph on that blast the added pitch is **45 degrees (0.7853982 rad)**; with a pitch graph it is **graph(d) x pi/180 rad** where `d` is the distance from the shot origin (the view origin with the shooting purpose, section 5.1) to `GetExactShootTarget(sb_fScatteringDistance of that blast)`. Then the pause for turning: **min delay when `sp_bSkipLookMatchPause`, else `GetMatchDesiredLookTime()`**: think `WaitBeforeCGS` after it. |
| 4 | `WaitBeforeCGS` | `sp_fWaitBeforeShooting` above 0: think `PlayPreparingAnimForCGS` after that; otherwise call it at once. |
| 5 | `PlayPreparingAnimForCGS` | a new cloned animation state with the lerp time; **if `sp_idPrepareAnimation` is set**: it becomes the played animation and is played **once** (mode 0, speed 1, strength 1), think `OnEndPreparingAnimForCGS` after **max(its length, 1e-5)**; otherwise go to step 6 (`DoConsecutiveGenericAiming`). `OnEndPreparingAnimForCGS` clears the animation state (lerp 0), removes the played animation and goes to step 6. |
| 6 | `DoConsecutiveGenericAiming` | **`sp_fAimTime` above 0**: if `sp_idAimAnimation` is unset call `OnAimingFinished` at once; else the aim animation is played once (new state with the lerp time **only when `sp_bLerpInAimAnimation`**, otherwise lerp 0) and think `OnAimingFinished` after **`sp_fAimTime`** (not the animation length). `sp_fAimTime` 0 or less: go to step 8. |
| 7 | `OnAimingFinished` | if the aim animation is set: new state (lerp time **only when `sp_bLerpOutAimAnimation`**), remove it. Go to step 8. |
| 8 | `DoConsecutiveGenericShooting` (**one shot**) | see below. |
| 9 | `UnprepareCGS` | a looping first shoot animation is removed (new state with the lerp time, remove). Then **if `sp_idPrepareAnimation` is set and `sp_bUnprepareAsInvertedPrepare`**: the prepare animation is played in **mode 4 (inverted)**, think `OnUnpreparingAnimFinished` after **max(length - lerp time, 1e-5)**; **else if `sp_idReloadAnimation` is set**: it is played once (mode 0), same delay formula; **else** `OnCGSFinished` at once. `OnUnpreparingAnimFinished` removes the animation and calls `OnCGSFinished`. |
| 10 | `OnCGSFinished` | **`sp_fWaitAfterShooting` above 0**: think `OnAfterShootingDelayFinished` after it; else call it at once. |
| 11 | `OnAfterShootingDelayFinished` | the added pitch is set back to 0; think `OnPuppetRotationFinished` after `GetMatchDesiredLookTime()`; `OnPuppetRotationFinished` is `SetState(PS_DEFAULT)`, whose exit hook is `OnEndCGS`. |

`OnContinueCGS` (think `AdjustPoseForCGS` after the min delay) lets a caller restart a series at step 3.

**`GetMatchDesiredLookTime`** (read): the time the puppet needs to turn from its current look direction (heading and pitch, in radians, each difference **wrapped into [-pi, pi)**) to the desired one: with the look rotation velocity `w` (a puppet function, `GetLookRotationVelocity`, rad/s): **w <= 0 gives 1e-5**, otherwise **max(|dheading|, |dpitch|) / w**. (The rotation velocity itself belongs to the movement spec, T01-141.)

**One shot (`DoConsecutiveGenericShooting`).** In this order:

1. **Stop test (AI only).** If `sp_fStopAttackAngle` is above 0, the puppet has **no operator** (no player brain) and has a target: the angle between the puppet's front direction and the direction from its shooting origin to the target (the target's `GetExactShootTarget(10)` when the target is a puppet, else its position) is computed in degrees (`acos` of the clamped dot product x 180/pi); **if it is greater than `sp_fStopAttackAngle` the series ends at once (`UnprepareCGS`)**.
2. **Choose the shoot animation.** `sp_asaShootAnimations[index mod count]` where the index is the **blast counter** (it increases by 1 at every shooting-blast event, section 5.1, and is reset by `ResetDynamicMembers`; so two blasts per shot advance it twice). If `sa_bTerm` is set the id is a scheme term and is remapped through the model's animation scheme (`samRemapSchemeAnim`; `ans.md`/`mdl.md`; 0 of the 137 records set it); otherwise it is the animation id itself. **No animation: the console says "Shoot animation is not defined in shooting process ..." and the series ends (`UnprepareCGS`).**
3. **Ammunition.** `sp_pfPlayerFire` 1 uses the puppet's primary ammunition count, 2 the secondary, 0 none. A count of **0 ends the series** (and plays the global "no ammunition" sound); a count above 0 is **decremented by 1** per shot; a **negative count is unlimited** (the placed puppets store -1).
4. **Timing.** `length = sa_fShootPeriod` when it is above 0, else the animation length. `elapsed` = time since the last shoot animation started. If a non-looping animation is chosen or this is the first shot, a new animation state is made with the lerp time when `sa_bLerpShootAnimation`, otherwise lerp 0. **`length <= elapsed`: call `PlayCGSAnim` now; else think `PlayCGSAnim` after `length - elapsed`.** (So the interval between two shots is never shorter than `length`.)

**`PlayCGSAnim`.** `L` = the animation length; the duration `D` = `sa_fShootPeriod` if above 0, else `L`; **the animation speed is `L / sa_fShootPeriod` when the period is above 0 and `sa_bScaleAnimationSpeed` is set, else 1**. The last-shoot-animation time := now. `D := max(D, 1e-5)`. **Looping animation** (`sa_bLoopShootAnimation`): it is started (mode 1, with the speed) only for the shot with index 0, think `OnSingleShootFinished` after `D`, **the shot index +1** at once. **Not looping**: started once (mode 0), think `OnCGSAnimFinished` after `D`; `OnCGSAnimFinished` removes the animation (new state with the lerp time), **adds 1 to the shot index**, then if `sp_idConsecutiveShootReloadAnimation` is set plays it once and thinks `OnReloadingAnimFinished` after its length (which removes it and goes on), else calls `OnSingleShootFinished`.

**`OnSingleShootFinished`:** **the series ends (`UnprepareCGS`) when the series start time plus one simulation step is already in the past and the shot index is at least the number of shots**; otherwise the next shot (`DoConsecutiveGenericShooting`) begins. So exactly `count` shots are made (the index counts finished shots), a count of 0 or less ends after the first finished shot, and a series never ends in the tick it began.

**The shooting happens in the animation.** The shoot animation of the model carries `Shoot blast (<id>)` events (129 in the data; `helper-classes-events.md`): the event time inside the animation decides when the shot leaves; at speed `L / period` the event moves with the scaled animation. An animation without such an event fires nothing.

## 5. The shot: `OnAnimEventShootingBlast` and the shooter

### 5.1 The event

`OnAnimEventShootingBlast(blast id)`: ignored without a current attack. With the current process: **an unknown blast id prints "Blast of type ... can't be found in shooting process ..." and does nothing**. Otherwise the **blast counter +1**, the current blast := the id, and the **ratio over consecutive shots** `r = (count > 1) ? index / (count - 1) : 0` is computed, where `index` is the shot index of section 4. For a non-looping shoot animation the index is incremented when the animation ends, so the events of shot k (counted from 0) see `index = k` and **r runs from 0 (first shot) to 1 (last shot)**; for a looping animation the index is incremented when the shot starts, so r runs from 1/(count-1) up to count/(count-1) (above 1 on the last shot; the graphs clamp, section 9.3) (**medium**); the puppet's shooter is told **`GenericOwnerShootOntoFoe(attack id, blast id, r)`** (5.2); the current blast is cleared. `GetShootingOriginAttachment` returns the blast's `sb_idBarellAttachment`, or **`Barrel01`** without a current attack or blast. `GetViewOrigin` with the shooting purpose (value 1) returns the **placement of that attachment** on the model (orientation from the attachment, position the attachment's absolute position; **medium**; the other purposes are eyes and cameras: `camera-view.md`). Below `O` is that **shot origin**. `GetExactShootTarget(d)` (read): with an **operator**: if the operator has an aimed entity, that entity's view target when it is a puppet (or its ride's) else its position; with none, **the stored operator aim point** when a puppet question answers yes (name unresolved: the player's puppet) else `O` + `d` x the shoot direction; **without operator**: the target when it is a puppet: its **view target** (its ride's when it rides); a target that is not a puppet: its position; no target: `O` + `d` x the shoot direction.

### 5.2 `GenericOwnerShootOntoFoe(attack, blast, r)` (the shooter; read)

Let `T0` = `GetExactShootTarget(sb_fScatteringDistance)`, `D` = the scatter distance, `dist = |T0 - O|`, `u` = the unit vector from `O` to `T0` (0 when degenerate).

1. **Scatter.** The shooter's scatter distance := `D`; its minimum and maximum scatter radii := **s x `sb_fMinScatteringRange`** and **s x `sb_fMaxScatteringRange`**, where `s` = the scatter graph at `r` (`sb_pgrScateringOverConsecutiveShoots`) or 1 without graph. (The ring model that uses them is `projectile-classes.md` 6.3.)
2. **Miss offset.** `UD` = the up/down graph at `r` (0 without graph), `LR` = the left/right graph at `r` (0 without graph; never set in the data). With `D` above 0: the point `P = O + u x D` is moved by `LR` along the local x axis and `UD` along the local y axis **of a frame with the aim's heading and pitch** (heading from `u` as `atan2(-ux, -uz)`, 0 when `|uy|` is above 0.99; pitch `asin(uy)`), and **the aim point becomes `O + unit(P' - O) x dist`**. With `D` 0 or less: the aim point is `O + u x dist` (no miss).
3. **Prediction.** The ratio `k` is **the prediction graph at `r`** when `sb_pgrPredictionOverConsecutiveShoots` is set. **Without that graph the code draws a random number and returns `sb_fMinPredictionRatio` + 0 x the draw: the maximum is never read** (verified in the instruction listing: the minimum is loaded twice; **medium**; the draw still consumes one value of the global generator per blast). The **lead velocity is `k` x the target's velocity** (the target entity's velocity vector; zero without a target; all three components, unlike the tool throw of section 8).
4. **Bullets (`bf_ctBullets` above 0).** The shooter is filled: bullet count, damage per bullet, damage type, bullet type; **bullet velocity = the global default (`CBulletParameters`, 80) unless `bf_fBulletVelocity` is above 0; reach = the global default (160) unless `bf_fBulletReach` is above 0** (`projectile-classes.md` 6.1). **Physical bullets (type 0)**: the direction is the propelled solution (section 9.2) for the aim point, the lead velocity and the bullet velocity, `ClampShootOriginAngles` (5.6) is applied and `FireBullets` runs from `O`. **Ray types (1, 2, 3)**: the direction is simply `O` to the aim point (**no lead**), then the same clamp and `FireBullets`. Of the 22 blasts with bullets 19 are type 1, one each type 2 and 3, and **one is type 0** (physical).
5. **Projectile (no bullets).** Nothing happens without projectile parameters. **Not `PF_FALLING`** (flat flight): the direction is the propelled solution with the projectile's own speed (the parameter file's flying-speed member, `bp_fFlyingSpeed`; matched by position, **medium-low**) (9.2); **if the projectile adds the shooter's velocity (`bp_bAddShooterVelocity`) the solved velocity is increased by the owner's velocity component along it** (`v := v + unit(v) x (ownerVelocity . unit(v))`; sign as read, **low**). **`PF_FALLING`**: the **launch pitch** is `min(asin(clamp(dy / dist3d)) + graph(dist3d) x pi/180, 81 degrees)` where `dy` is the height difference to the aim point, `dist3d` the straight distance and `graph` the blast's pitch graph (**45 degrees when it has none**); the launch is solved with the free-fall solver (9.1) with the minimum and maximum speed 0 and 3e38 (success = "a solution exists"); **if the speed is above 0.1 it is then clamped into [`sb_fMinThrowingVelocity`, `sb_fMaxThrowingVelocity`]** keeping the direction (three blasts have min = max, which makes their speed a constant 50 or 60). **The projectile is launched only when the solver reported success** (the required pitch must be at least the elevation of the aim point, section 9.1; for the propelled solver, convergence in fewer than 10 iterations), through the shooter's `FireProjectile(parameters, fire power 0, launch speed = |v|)` after the orientation is set from the direction (`pitch = asin(vy)`, `heading = atan2(-vx, -vz)`, 0 when `|vy|` is above 0.99).

### 5.3 What the shooter's `FireProjectile` does

On a client nothing. On the host: the shooter's placement is turned into a matrix and back, **`samIsShootingFromWall` is asked** (owner, placement): when it names a wall entity, **the origin is moved back by 0.5 x the vector it returns**; a `CGenericProjectileProperties` is created with the owner, the parameter file, the fire power (0), the launch velocity, the placement, the damage inflictor weapon of the shooter and the wall entity, spawned (`SpawnEntity`) and the properties object is deleted. **Medium.**

### 5.4 Unused data

`sb_fMinThrowPitch`, `sb_fMaxThrowPitch` and `sb_idProjectile` are not read here, and **none of the functions of this page reads `SPuppetProjectileParams`** (126 files with min/max throw pitch, distance, predict and undershoot ratios: `projectile-classes.md` 8.3), so those numbers may be dead data or used by code not read (T01-260); a pitch graph on a blast whose projectile is not `PF_FALLING` is read by nothing in this chain (10 blasts). **Low** (absence in the functions read).

### 5.5 `GetPlayerFireType`

`PlayerFire` of a fire button: button 0 -> 1, button 1 -> 2, other -> 0 (read). `CPlayerPuppetEntity` has its own `IsFlippingFireButtons` (T01-264).

### 5.6 `ClampShootOriginAngles(blast, owner placement)`

Both the aim orientation and the owner's orientation are turned into Euler angles; the **heading difference and the pitch difference are wrapped into [-pi, pi) and clamped to +-`sb_fBarrelShootoutDeclineH` and +-`sb_fBarrelShootoutDeclineP` degrees**; the result is the owner's heading and pitch plus the clamped differences (roll from the aim). So a barrel can turn at most 45 degrees (the value of 145 blasts) from where the puppet looks, whatever the foe's position. **Medium** (the placement argument was matched by its use in the caller; **medium-low**).

## 7. Melee and run-over blasts: `OnAnimEventMeleeDamage(blast id)`

Triggered by the animation event `Melee blast (<id>)` (36 events in the data) of the melee animation (`GenericMeleeAttackState` plays `ma_idAnimation`, remapped through the model's animation scheme, once, mode 2, after a new clear state and `StopMoving`; think `OnMeleeAnimFinished` after **max(length - lerp time, 1e-5)**; `OnMeleeAnimFinished` tells the brain `OnActionFinished` and sets `PS_DEFAULT`; the state also clears the "melee hit the foe" and "damage applied" flags).

The function (read in full):

1. **Does nothing when the puppet has no target entity.** (So a melee blow needs a foe set on the puppet.)
2. The attack is looked up by the current attack id **first among the puppet's melee attacks, then among its run-over attacks**; neither: the console prints "Attack ... can't be found in melee or run over foe attacks"; the blast is looked up by id in that attack's blast list ("Melee blast with ID ... can't be found in melee attack / run over foe attack"). **The run-over attack's blasts are applied by exactly this function**; the stages of the run-over itself (`ROFS_*`) are the behavior's (T01-152).
3. **If `mb_bDamageChainStart` is set the "damage applied" flag is cleared; nothing is done while the flag is set.** The flag is set to 1 only by the legged leap's hit handler (`OnHullTouchedInternal`, T01-147) and cleared by every melee start, so **for melee it is never set and the test always passes** (and the single blast with `mb_bDamageChainStart` 0 behaves like the others): **medium** (the writers of the member were scanned over the whole DLL).
4. **Origin** = the absolute position of the model attachment named by `mb_idAttachment` (the model renderable's attachment placement). If the attachment cannot be found (the placement equals the default identity) the console prints "Melee damage can't be performed because attachment ... position can't be obtained" and nothing happens.
5. **Victims.** All collision hulls within **`mb_fDamageRadius`** of the origin (`cldGetHullsInRange`; the sphere test against the hulls, which hull categories take part was not read: T01-261). For each hull: its owning entity must exist, **must not be the attacker, must not already be in this event's list of victims** (so one entity is hit once per event even with several hulls), and **must answer yes to `CanReceiveRangeDamage`** (puppets answer yes; `puppet-entity-classes.md` section 7). Others are skipped.
6. **The damage record** for each victim: attacker = the puppet; the hit hull; the **amount = `mb_slDamage` converted to an integer (truncation; a float member)**; **when `mb_slEnvironmentDamageOverride` is above -1 and the victim is not a puppet, the amount is the override instead** (500 in the one blast that has it); the damage type `mb_dtDamageType` (4 in all); the origin as the hit point; the **direction** `dir = Rq x (-cos(P) sin(H), sin(P), -cos(P) cos(H))` where `H` = `mb_fLaunchHeading` and `P` = `mb_fLaunchPitch` in radians and `Rq` is the rotation of the **puppet's absolute orientation** (quaternion in the engine's x, y, z, w order, standard rotation of a vector); the **impulse** = `dir x mb_fFoeKickImpulse`. The owner's damage multiplier is **not** applied here. In the engine's frame the forward axis is negative z, so heading 0, pitch 0 pushes straight forward; **positive heading turns the push towards the puppet's negative x**, positive pitch lifts it.
7. **Kick.** If the hull has a body, **the impulse is added to the body at the body's own position** (`CBody::AddImpulse`) **before** the victim is told, and the damage record carries the same impulse; whether a victim then takes it twice (once from the body impulse, once from the record, e.g. a puppet's accumulated force impulse) is not resolved (T01-140).
8. The "melee hit the foe" flag of the attacker is **or-ed with "victim is the target entity"** (read by the brain's `CBAVTMeleeSuccess` validity term, `behavior-action-classes.md`). The victim receives the record through **`OnReceiveDamage`** (alignment rules of `ReceivesDamageFrom`, invulnerability, the co-op multiplier and everything after: `puppet-entity-classes.md` section 7, T01-140).

## 8. The tool launch (`LaunchTool`, `CThrowDescription`)

**Entry.** `ThrowTool(tool, throw description id, target entity)` (a remote call, host first): on every machine it removes the tool from the desired tools, sets the attached tool's state to "throwing" (value 2) and stores the description id and the target handle on it. `ThrowPickedTool` and `ThrowPickedToolAtTargetEntity` (default target: the puppet's target entity; none: nothing) throw the tool taken from an entity, `macThrowTool` the named tool. **`StartThrowingTool`** maps the tool's throw animation through the scheme; **if the model's animation has a "detach tool" animation event the state becomes 13 and the tool is thrown when the event fires; without the event `LaunchTool` runs at once**. `ThrowDeathTools` (called by the death animation event `OnAnimEventDeathThrowTools` unless a virtual question of the puppet, name unresolved, answers yes) launches every attached tool that has a certain tool flag set (name unresolved; by the function name it marks tools that fly off on death) and detaches it. The tool state numbers (`CTA_`) are T01-144; here: 2 throwing, 13 waiting for the detach event, **14 (0xe) = launched**.

**`LaunchTool(tool)`** (read; the launch geometry of the path with an entity was only followed in outline):

1. The tool must be attached; its placement relative to the puppet is fetched (`GetToolRelPlacementInPuppet`); **if the tool's "upright" flag is set only its heading is kept**.
2. **No target entity** on the attached tool: the **random launch** of `CLaunchVelocities::CalculateLaunchVelocities` (below) gives the linear and angular velocity and nothing else is computed.
3. **With a target**: `T` = the target's view target if it is a puppet, else its position; `O` = the tool's start position; `d = T - O`, `dist = |d|`. The throw description is found by its id in the puppet's `pp_atdThrowDescs` (`GetThrowDescription`; a linear search); **not found: the console warns "Can't find throw description ... Using default throwing parameters", with pitch 45 degrees (0.7853982 rad), underhit 0, prediction 1, minimum speed 0, maximum 3e38**. Found: **pitch = pitchGraph(dist) x pi/180, underhit = underhitGraph(dist), prediction = predictionGraph(dist)** (`CThrowDescription::CalculateParams`), the speed window from the description.
4. If `dist` is above 1.2e-7: **the aim point is pulled back towards the thrower by `underhit` metres: `T' = T - d/dist x underhit`** (a negative underhit aims beyond the target).
5. **Launch pitch = `min(asin(clamp(dy / dist, -1, 1)) + pitch, 81 degrees (1.4137167 rad))`** with `dy = d.y`.
6. **Lead velocity = prediction x (target velocity x, 0, target velocity z)** (the target's vertical speed is ignored).
7. The **free-fall solver at fixed pitch (9.1)** is called with `O`, the pitch, `T'`, the lead velocity and the speed window `[min, max]` of the description: it returns the launch velocity (**speed clamped into the window, direction kept; the success flag is ignored here**).
8. **Applying it.** If the attached tool already has an entity (a picked object): that entity is re-placed at the tool's placement, **its linear and angular velocity are set** (angular zero in the target case). Otherwise, **on the host, if the tool has an entity creator** (`CBaseItemToolEntityCreator`, debris creator: `projectile-classes.md`, T01-161), a new entity is created from it at the placement with the velocities and a **stretch = the tool's scale x the model's stretch (the model stretch only when the tool's "scale with model" flag is set)**. Both paths store the entity in `en_henLastThrownToolEntity` (read by the script function `macGetLastThrownTool`) and **set the attached tool's state to 14**. (How the world placement is composed in the first path, and the creator's interface, are T01-262.) **Medium**; steps 3 to 7 were each read directly.

**The random launch** (no target) is `CLaunchVelocities::CalculateLaunchVelocities` of the tool's `ct_lvLaunchVelocities` (68 `.ctl` records; specified in `projectile-classes.md` section 8.1). Re-read here: the draws are made in the order speed, heading, pitch, then the three angular velocities (each a draw of the global generator `mth_ulRandom`); the angular velocity members are degrees per second and the **output angular velocity is in radians per second**; the first member (`lv_bRelativeToAttachment`) selects the attachment named by the call (flag set) or the model's own placement (clear) as the frame the velocity is rotated by (**medium**; consistent with the earlier page).

**The data (`CThrowDescription`, 30 in 15 files; script section 6).** Per description: three graphs and a speed window. Names (the stored identifier) and values:

| Description | Count | Pitch graph (degrees) | Underhit graph (metres) | Prediction | Speed window |
|---|---|---|---|---|---|
| `ThrowItem` | 11 + 2 | constant 45 | linear: -1 at 0 m, 3 at 10 m (clamped outside); 2 files: constant 3 | 0 | 10 to 30 |
| `ThrowFar` | 4 + 9 | constant 45 | linear -1 .. 3 (4); constant 3 (9) | 0 | 10 to 80 |
| `CommonThrow` (`kwongo.ep`) | 1 | constant 15 | constant 0 | constant 1 | 0 to 3e38 |

## 9. The two numeric solvers

Gravity is the world's gravity vector (every world stores (0, -30, 0): `wld-root.md`); `g` = its length, 30. **Medium** (read).

### 9.1 Free fall at a fixed pitch (`samGetFreeFallingLaunchParamsForFixedPitch(O, pitch, T0, vT, min, max)`)

Up is the y axis. Start with `T = T0`, previous time 0. Repeat at most 10 times: `d = T - O`, `h = d.y`, `R` = length of `d` without y. **If `atan(h / R)` is greater than `pitch` return failure.** `t = sqrt((2 / g) x (R x tan(pitch) - h))`; `T := T0 + vT x t`; stop when `|t - previous| <= 0.01`, else previous := t. After the loop **with the `d` of the last iteration (taken before `T` was moved)**: **velocity `v = (d - 0.5 x gravity x t^2) / t`** (`gravity` the vector (0, -g, 0)). If **`min < |v| < max` return success**; else the speed is clamped into [min, max] (direction kept) and the call reports failure. The aim point `T` after the loop is also returned.

### 9.2 Flat flight at a given speed (`samGetPropelledLaunchParams(O, T0, vT, speed)`)

`t = 0`; repeat up to 10 times: `P = T0 + vT x t`, `t' = |P - O| / speed`; **stop when `|t' - t| <= 0.01`** else `t := t'`. The velocity is `unit(P - O) x speed`. **Success unless the loop used all 10 iterations** (a convergence on the 10th also counts as failure).

### 9.3 The graphs (`Engine.dll`; read)

`CValueGraph`: the one value x the graph's y stretch. `CLinearGraph`: the control points sorted by x; **x is first multiplied by the x stretch factor** (the member stored as `CGraph.8`, in the data 1 except a pitch graph with scale (10, 100)); below the first point or with one point: the first y; above the last: the last y; between: linear interpolation (and the mean of the two y when two points share an x); all results x the y stretch (`CGraph.7`). `CStepUpGraph` / `CStepDownGraph` (the same code): **linear between the first two control points, clamped to the first y before the first x and the second y after the second x** (the "step" is a ramp). The stretch members of the 5 graph kinds on the blasts: pitch graphs 1 x 1 in 31 cases and 1.4, 1.6, 2, 3 or (10, 100) in the others (script section 4).

## Invariants

1. Of the 168 blasts **none has both bullets and a projectile** (22 with bullets, 145 with a projectile, 1 with neither); all bullets blasts have velocity -1 (global default).
2. Every melee blast has damage type 4; `mb_bDamageChainStart` is 1 in 74 of 75 and the flag has no effect on melee (section 7 step 3).
3. The left/right miss graph is null in all 168 blasts; the prediction ratio minimum equals the maximum in 143 of 168 (the code uses only the minimum, so the other 25 are read as their minimum: the maxima 0.2, 0.5, 0.85, 1 of those pairs have no effect).
4. 3 blasts have a minimum speed above 0 and are the only ones with a maximum below 1000 (all `PF_FALLING`); all 30 throw descriptions have graphs of kinds value, linear (underhit only) and value.
5. State 6 allows one series at a time (`CanPerformGenericShooting` is false inside it) and the shot index increases exactly once per finished shot (and once more per looping shot start).
