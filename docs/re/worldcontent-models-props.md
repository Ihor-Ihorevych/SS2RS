## Summary

- **`CStaticModelEntity`** is the placed model: **25,383 entities in all 59 worlds** (35 % of the 73,098 entities), each with a record of the same stem. It is the level's scenery, its animated and its destructible parts. It owns a model renderable and, when "Collision" is on (21,420 of 25,383), a physics mechanism; it can play animations, disappear and appear, be used by the player and be destroyed. Saved under its exported name.
- **`CPropEntity`** is the free physical object (crate, barrel, ...): **1,726 entities in 32 worlds**, always with a mechanism, a splash and a dust effect, and a destruction sound source. Saved as `SPropEntity`. A prop can be **made by a spawner** (36 are) and can be **carried as a tool** by the player.
- **The two classes share one family of members** (model, stretch, shader modifiers, parent part, cull distance, fade length, shadow type, death spawner, mechanism name, "Control by macro" or "Physics enabled") but not code: a static model is steered by macros and the record flags; a prop is a rigid body with a state that replicates (20 of 44 members).
- **Damage and destruction are flags plus the model's destruction data**: a model is destructible unless its record says "Disable destruction" (2,064 static models); damage can be ignored, reported or limited to kicks by macro functions (section 2.4).
- **Net.** A static model is replicated only when it is macro-controlled (536) or has a destruction holder; a prop is dynamic unless a spawner made it (overview, section 4).

## Layout / rules

### 1. `CStaticModelEntity`

**Role.** One model in the world. `OnCreate` copies the record, loads the model (or builds an empty model with one mesh when the record has none), makes a **model renderable** (stretch, fade length, cull distance, shader modifiers, shadow type), sets the placement, builds the **physics mechanism** when "Collision" is set, and makes two **sound sources** (`en_hssAlive`, `en_hssDestruction`). Two readings agree that the mechanism exists exactly when the record's "Collision" flag is 1: **21,420 of 21,420** collision records have a mechanism handle, **3,963 of 3,963** others have none (script). The hull handle `en_hhuHull` is null in all 25,383 (the hull is part of the mechanism).

**`OnCreate` step by step (T01-175, read in full, R).** In order: (1) validate the record is a `CStaticModelProperties` or clear it; (2) copy the mechanism name and macro-control flag (members 11/12 of section "Members" above) and the "disable destruction" word; (3) copy the seven-float original placement; (4) null the parent-prop handle; (5) set the "ignored by navigation" base-entity flag from the record; (6) if the record has no model configuration, create an empty one with one empty mesh (`mdlCreateModelConfiguration` + `mshCreateMesh` + `mdlModelConfigAddMesh`) so every static model always ends up with a model configuration even without a `.mdl`; (7) allocate the `CModelRenderable`, set it as the model, set stretch/fade length/cull distance from the record, point the renderable's owner back at the entity, and set the aspect's absolute placement from the record's placement; (8) set the renderable's shadow flag from the record's `EntityShadowType` — shadow type 0 ("none") **sets** the renderable's "no shadow" bit `0x800000`, type 1 ("static") **sets** a different bit `0x40000` ("static shadow"), and type 2 ("dynamic") sets **neither** bit, leaving the renderable's own default (ordinary dynamic shadow) untouched — matching the existing "none = no shadow, static = static shadow, dynamic = none" line below; (9) copy the shader modifier list onto the model instance when the record has any modifiers; (10) **clamp the sound ranges**: hot spot is clamped to at least 0, then fall-off is clamped to at least the (already-clamped) hot spot — confirming the Evidence section's existing claim that "the clamp rewrites the record" (both clamped values are written back into the record's own fields, not just the entity's copies); (11) allocate the two sound sources (`en_hssAlive` at the alive slot, `en_hssDestruction` at the destruction slot) and initialise each with `samInitializeSoundSource(handle, entityHandle, aspectHandle)`. Separately, `GetOriginalPlacement()` (read in full, R) — the accessor used by `Appear`/`DoAppear` and `ResetDynamicMembers` to restore the placement — reads `en_qvOriginalPlacement` back and, **only when `en_henParent` is set**, composes it with the parent entity's own current absolute placement (a standard quaternion/position compose against `GetAbsPlacement` on the parent) before returning it; with no parent it returns the stored placement unchanged. The physics mechanism itself is **not** built here: `SetupCollision` (see below) is a separate virtual hook the base entity machinery calls after `OnCreate` when "Collision" is set.

**`SetupCollision` (R).** Guards: does nothing if called with a null model configuration, or if the record's "Collision" flag (member 11) is 0. Otherwise it re-checks whether the *current* model configuration already has a mechanism for the entity's stored mechanism identifier (member 12); if not, and the identifier is not the invalid id, it logs `StaticModelEntity::SetupCollision(): Model "<file>" doesn't have mechanism with given name!` to the info console and returns **without** building anything (so a model whose record names a mechanism the model file doesn't actually have ends up with no mechanism at all, silently, besides that one log line). If the identifier resolves (or is invalid, meaning "use whatever the model has"), it allocates a new `CMechanism`, builds it either as a plain mesh mechanism (`CreateMeshMechanism`, when the *new* configuration parameter doesn't have the named mechanism either — i.e. a hull-only fallback) or as the named mechanism (`CreateMechanism`), sets its collision category from the mechanism's own name string (`strConvertStringToID` of the mechanism identifier), places it at the entity's absolute placement, and — if the mechanism's first part aspect is a `CHull` and the record names a parent prop whose aspect's own relevant part is also (or derives into) a `CBody` — links that body to the hull via `CHull::SetBody` (this is the "glue hulls to bones"/parented-mechanism wiring; it silently does nothing when the parent doesn't resolve to a body).

**`ResetDynamicMembers` (R).** Clears the macro-wait id, resets the "sleep until" time to `Time(-100.0)` (i.e. already elapsed), clears the "disappeared by the animation system" word and the client offset-error accumulator. Only when the model renderable exists: clears the "is hidden" shadow of the current animation state (`ResetAnimationParams`, the same defaults as the constructor), clears the model's animation queue, resets the aspect to the stored original placement, and — if the record has an auto-start animation and that animation still exists on the (possibly re-mapped, `samRemapSchemeAnim`) model — clears the state and starts it fresh (`NewClearState` then `PlayAnimation(..., loop=1, speed=1, ...)`). Finally, if the model's animation queue already has pending events, it calls `EnableAnimationEvaluation` to (re-)arm the animation-event machinery. This is the "boot again"/re-entry reset used when a model configuration is swapped in (`ChangeToModel`, a destruction phase) or the entity otherwise needs to look freshly booted.

**`ModelFlags`** (the DLL's names; **medium**): `MF_CAN_BE_USED` (1: the player can use the model, `EnableUsage` and `DisableUsage` set it), `MF_REPORT_DAMAGE` (2: raise the macro event once on the next damage), `MF_IGNORE_DAMAGE` (4: set while a destruction is running), `MF_IGNORE_KICKING_DAMAGE` (8: kicks do nothing), `MF_IGNORE_NON_KICKING_DAMAGE` (16: only kicks hurt), `MF_DISABLE_KICKED_DESTRUCTION_CASCADING` (32: a kicked model passes zero damage on), `MF_PROPERTIES_DISABLE_DESTRUCTION` (**65,536, high: the data**; copied from the record's "Disable destruction"). The values 1 to 32 follow from the DLL's list order and the bit tests in `OnReceiveDamage` and `GetObjectManipulationFlags` and are **medium**.

**Record** (`CStaticModelProperties`, 18 members; labels are the DLL's): `.1` `ep_pmcModel` "Model"; `.2` `ep_vStretch` "Stretch"; `.3` `ep_smlModifiers` "Shader modifiers"; `.4` `ep_bCollision` "Collision" (default 1); `.12` `ep_idMechanism` "Mechanism"; `.5` `ep_fCullDistance` "Cull distance" (default −1); `.6` `ep_fFadeLength` "Fade length" (−1); `.7` `ep_idParentPart` "Parent part"; `.8` `ep_idAutoStartAnim` "Auto start animation"; `.9` `ep_estShadows` "Shadows" (`EntityShadowType`: 0 none 24,167, 1 static 55, 2 dynamic 1,161); `ep_fSoundFallOff` "Sound fall off" (default 50) and `ep_fSoundHotSpot` "Sound hot spot" (10); `ep_bMoveHulls` "Glue hulls to bones"; `ep_hepDeathSpawner` "Death spawner" (record 220 set) and `ep_henDeathSpawner`; `ep_bDisableDestruction` "Disable destruction" (2,064); `.14` `ep_bIgnoredByNavigation` "Ignored by navigation" (492); `ep_bControlByMacro` "Control by macro" (536).

**What `OnCreate` does with the record (R for the copies, P for the order).** Mechanism name, collision flag, "Control by macro" and the sound ranges are copied to the entity; "Disable destruction" sets `MF_PROPERTIES_DISABLE_DESTRUCTION`; "Ignored by navigation" sets `BEF_IGNOREDBYNAVIGATION` in the base flags (**high: 492 of 492, and no other entity has the flag**); the shadow type sets a renderable flag (none = no shadow, static = static shadow, dynamic = none); the sound ranges are clamped to be non-negative with fall-off at least the hot spot (the clamp rewrites the record). The model renderable gets the entity as its owner.

**Net.** Overview section 4: `NEB_STATIC` when `en_bControlByMacro` is set or the model configuration has a destruction holder with at least one configuration, else `NEB_NONE`; `GetRelevantDistance` is the renderable's effective cull distance.

**The 11-member animation replay, resolved (T01-175, `PreSendUpdate`/`PostReceiveUpdate`/`ApplyClientOffsetCorrection` all read in full, R).** The 11 replicated members are exactly the 10 "last animation command" members of row 54 above, each mirrored into its own net-shadow copy (`en_smaaNetAnimAction` … `en_fNetCurrentAnimOffset` of row 61), plus one computed member, the current animation's time offset:

- **`PreSendUpdate`** (host only; does nothing while the model has no renderable handle): copies all 10 "last command" members verbatim into their 10 net-shadow counterparts (a plain field-by-field copy, confirming row 61's "the 11 net copies of the animation command" is 10 direct mirrors plus 1 computed value). It then looks up the currently-tracked animation in the model's `CAnimQueue` by the command's animation id (`aniFindPlayedAnim`); if a valid playing instance is found, it computes `currentTime − animationStartTime` and stores that as the 11th member, `en_fNetCurrentAnimOffset`; otherwise it stores 0.
- **`PostReceiveUpdate`** (every machine): first handles appearance — if the model's current model configuration differs from the last-seen one, appears/disappears/`ChangeToModel`s as needed; then, independently, appears/disappears to match the replicated "hidden" flag against the renderable's own "disappeared" word. Then, only when the renderable exists: if **any** of the 11 incoming net fields differs from the current shadow (a field-by-field comparison, not just the action), it copies all 11 new values in as the new "last command" state and **replays exactly one action** by switching on the incoming action value — `2` → `StopAnimation`, `3` → `StopAllAnimations`, `4` → `NewClearState`, `5` → `NewClonedState`, `6` → `CModelRenderable::RemoveAnimation`, `1` → `PlayAnimation`, anything else (`0`, none) → no call. This is a direct reading of the dispatch, so it **confirms** (upgrades from inferred to read) the `StaticModelAnimAction` enum and order already stated in row 54: 0 none, 1 play, 2 stop, 3 stop all, 4 new clear state, 5 new cloned state, 6 remove. After replaying the action (or if nothing changed), it re-finds the tracked animation and computes `en_fClientOffsetError = (local elapsed time of the tracked animation) − en_fNetCurrentAnimOffset` — i.e. the client's own drift against the host's reported offset, 0 if the animation isn't currently valid locally. Finally, if the entity isn't already stepping, it enables `OnStep` (so the error can be melted on subsequent steps).
- **`ApplyClientOffsetCorrection`** (R; the per-step smoothing step `replication.md` already named for doors, movers and static models, formula parked at T01-098): runs only when the renderable exists **and** the current action equals the last-received net action (i.e. no new command arrived this tick — the same animation command is still in effect). It re-finds the tracked animation; if valid, it reads the two `CSamNetworkParams`/`ggp_snpNetworkParams` thresholds `snp_fIgnoredAnimOffsetError` (0.05) and `snp_fTeleportedAnimOffsetError` (0.5, `helper-classes-params.md` §3): below the first, `en_fClientOffsetError` is simply zeroed (error negligible, nothing to correct); at or above the second, the correction factor is `1.0` (full snap in one step); in between, it computes a step-size-dependent factor via the x87 `pow` intrinsic against `snp_fAnimOffsetErrorMeltingFactor` (5) — frame-rate-independent exponential melting, matching `snp_fPostionErrorMeltingFactor`'s role for position error, but **the exact exponent/base arrangement of the `pow` call is not resolved from this decompilation** (medium confidence only; T01-098 is the task that owns "the formulas … with the eight network-block constants"). Whatever the factor, it subtracts `factor × en_fClientOffsetError` from the error and **nudges the tracked animation's own start time** by the negated amount (`aniSetStartTime`), which is the actual correction mechanism: instead of popping the visible animation to the host's reported time, the entity slides the local animation's timeline a little every step until the drift disappears.

### 2. Behaviour of `CStaticModelEntity`

**2.1 Hooks it overrides** (vtable comparison with `SBaseEntity`; 117 slots, 12 new): `OnCreate`, `OnUpdate`, `OnDelete`, `OnStep`, `OnBoot`, `SetAbsPlacement`, `GetAbsPlacement`, `CollectForSortedIteration`, `GetNetBehavior`, `GetRelevantDistance`, `PreSendUpdate`, `PostReceiveUpdate`, `GetBoundingBox`, `GetAspectForAttaching`, `GetAllAspects`, `GetModelRenderable`, `CanReceiveRangeDamage`, `OnReceiveDamage`, `GetObjectManipulationFlags`, `EnableUsage`, `DisableUsage`, `GetMechanism`, `IsDestructible`, `ExecuteDestruction`, `GetPiercingProjectileResilience`, `BeDestroyedByPeircingProjectile`, `IsDestroyed`, `ContributeToGameTotalStats`. New hooks: `ApplyClientOffsetCorrection`, `SetupCollision`, `DeleteCollision`, `ResetDynamicMembers`, and the five animation-event hooks `OnAnimEventProduceSound`, `OnAnimEventProduceEffect`, `OnAnimEventProduceShakeEffect`, `OnAnimEventTerminateSound`, `OnAnimEventTerminateEffect` (the model's animation events play a sound, an effect or a shake and remember them so a later event terminates them; **R**, T01-175).

**Animation events, resolved (T01-175, `CStaticModelAnimEventsData` and `CStaticModelAnimEventHandler` read in full, plus the five `OnAnimEvent...` hooks, R).** `en_hsmaedAnimEventsData` (member 47) is a `CStaticModelAnimEventsData`, created on demand by `EnableAnimationEvaluation` and holding: a **4-slot round-robin pool of `CSoundSource`s** (`GetNextSoundSource` cycles slot order 0,1,2,3,0,… starting at slot 0, letting up to 4 anim-event sounds play concurrently without one cutting another off); **two event-id-keyed containers**, one for sounds and one for effects, that remember which handle a given animation-event id started; a small **`CStaticModelAnimEventHandler`** (created in the same constructor) that is installed as the model instance's `CAnimEventHandler` and simply forwards each callback — after checking the owner handle is still a live `CStaticModelEntity` — to the entity's own `OnAnimEventProduceSound`/`TerminateSound`/`ProduceEffect`/`TerminateEffect`/`ProduceShakeEffect` hooks; and the model's own **sound hot spot / fall-off** (`Initialize`'s last two float parameters, stored on the event data and later passed to `CSoundChannel::SetRange` with a fixed 360° cone). `EnableAnimationEvaluation` (R) creates this holder, calls `Initialize(ownerEntity, modelAspect, en_fSoundHotSpot, en_fSoundFallOff)` on it (which in turn calls `samInitializeSoundSource` on each of the 4 pooled sound sources) and enables `OnStep` if not already on. `OnStep` steps the holder while it has pending events and frees it once the model's animation queue has none left (section 2.2). The five hooks: `OnAnimEventProduceSound` takes the next pooled sound source, sets its range from the stored hot spot/fall-off, asks `samAnimEventProduceSound` to actually start it from the model instance and the raw anim event, and — only if the returned `CWeightedSound`'s flag bit 0 is set (a "needs explicit stop" sound) — registers it in the sound-termination container keyed by the event's id (`samAddSoundToTerminationList`); `OnAnimEventProduceEffect` asks `samAnimEventProduceEffect` to spawn the effect entity and, only if its own flag bit 0 is set, registers it the same way (`samAddEffectToTerminationList`); `OnAnimEventTerminateSound`/`TerminateEffect` simply look the event id up in the matching container and stop/remove whatever was registered under it (`samTerminateSoundFromContainer`/`samTerminateEffectFromContainer`); `OnAnimEventProduceShakeEffect` has no pooling or termination bookkeeping at all — it is a thin pass-through to `samAnimEventProduceShakeEffect` with the model handle, so camera shakes from anim events are fire-and-forget. All five first validate `param_1` is non-null, logging `"Invalid animation event occured. Static model[s] can only recognize '<kind> event' for playing [sounds/effects]."` otherwise. `samAnimEventProduceSound`/`samAnimEventProduceEffect`/`samAnimEventProduceShakeEffect` themselves (the functions that actually resolve an anim event's payload into a sound/effect/shake) were **not** read for this task — they are shared with the puppet and weapon anim-event handlers and are out of this page's scope.

**2.2 Life cycle.** `OnBoot` (R): marks the death spawner, applies the model to the renderable, and on the host (or when the entity does not hide itself) calls `DoAppear`; then plays the model's scheme sound for "alive" if the model has one. `OnStep` (R): while "Control by macro" is on and a mechanism exists, evaluates the mechanism's animation; also steps the animation-event holder and removes it when the model's animation queue has no events left; on a client it calls the net-apply hook; it disables stepping when nothing is left to do. `EnableAnimationEvaluation` (R) creates the event holder on demand and enables stepping. `OnUpdate` (P) re-reads the record (editor edit) and prints two diagnostics when a macro entity does not control a model flagged "Control by macro" (**"Static model entity with ID %1 is not controlled by any macro entity. Please turn off the ..."** and **"... can't be controlled by macro entity with ID %2 ..."**). `OnDelete` (P) frees the mechanism, the renderable tree and the two sound sources. `SetupCollision` (**R**, T01-175, step by step in section 1 above), `DeleteCollision` (P) build or remove the mechanism (a mesh mechanism for the model's hulls, the category from the mechanism name, logs `StaticModelEntity::SetupCollision(): Model "..."` when a model lacks the hull it needs). `ResetDynamicMembers` (**R**, T01-175, section 1 above) is the "look freshly booted again" reset used when a model configuration is swapped (destruction phases, `ChangeToModel`).

**2.3 Appear and disappear.** `Disappear` (macro) sets the renderable's hidden flag (`IsDisappeared` reads it) and `DoDisappear` also tells the virtual that removes collision (R); `Appear` clears the flag and re-creates the model at the original placement with the stored stretch (`DoAppear`, R). `OnBoot` appears the model on the host and, on a client, only when the entity is not hidden by its replicated flag.

**2.4 Damage and destruction.**

| Function | Rule (basis) |
|---|---|
| `CanReceiveRangeDamage` | true when the model has destruction data (R) |

**`ExecuteDestruction`/`DestroyOnePhaseLoop`, step by step (T01-175, R).** `ExecuteDestruction(phase)` does nothing if the model is already marked destroyed or already hidden; otherwise, if the record names a death spawner, it calls that spawner's `DeathSpawn`; then, if `samGetModelDestructionData` (the model's `CModelDestructionCustomData`, see below) returns a record with a positive debris count, it spawns debris through a profiled helper (a ray-casting debris scatterer shared with props and projectiles: it calls `cldCheckRay`/`rayGetHitPosition`/`rayGetHitDistance` to place and orient the pieces against whatever is under the model, respects `samIsDeathmatch`, and allocates/frees working arrays per debris piece — not transcribed line by line, see Confidence); finally it plays the model's scheme "destruction" sound if the model has one and calls `DestroyOnePhaseLoop(phase, isFirstCall=1)`.

`DestroyOnePhaseLoop(allowChaining, isFirstCall)` fetches the model's first destruction configuration (`samGetDestructionConfig`, always index 0 of the holder — see "The model destruction data" below) and does nothing if there is none. If the configuration's substitute model (`CDestructionConfig.2`) **is** the model's own current model (a configuration that points to itself), it logs `Model %1 features infinite destruction loop.` and just disappears the model — this is the only place that log is possible, and it is a defensive check against malformed data, not a normal path (`destruction.md` already notes "no substitute is its own model" in the shipped data). Otherwise it computes the model's `|stretch.x| + |stretch.y| + |stretch.z|` scaled by a constant and calls `CDestructionConfig::CreateEffects` with it (the per-effect `.3` list: debris, particles, sound, shaker — `destruction.md` section "The stored structure"), passing the configuration's own `.7` flag through to every effect. Then, **only when the configuration has no substitute model** (the terminal phase of a chain): it stops the alive/destruction sound channel; if there is no original model either, it just disappears; otherwise — the main physics-destruction branch — it snapshots the mechanism's own sub-mechanism list, rebuilds the hull/collision via the base `Destroy`, applies the baseline update, re-collects that same sub-mechanism list into the parent's **ignore list** (`CMechanism::AddIgnoreList`, so the freshly-detached pieces don't immediately re-collide with the parent) and plays the model's scheme sound keyed by a (currently unidentified, read as a raw string constant) sound name. Regardless of which branch ran, it then clears the animation state (`NewClearState`) and, if the configuration names a "stop" animation it plays it in stop mode, and if it names a "play" animation it starts it looping — these are `CDestructionConfig`'s own two `IDENT` slots (`destruction.md`'s `.5`/`.8`, not disambiguated further here, see Open questions). Finally, **if this was the terminal-phase branch and chaining is allowed**, it recurses once more as `DestroyOnePhaseLoop(allowChaining=1, isFirstCall=0)` — this is how a multi-phase destruction chain (`phase_01` → `phase_02` → …, `destruction.md`) walks itself to the end in a single call instead of needing one `ExecuteDestruction`/`macDestroyOnePhase` per phase.

**The model destruction data, resolved (T01-175, R; `Engine.dll` and `Sam2Game.dll`).** `samGetDestructionConfig(modelRenderable)` resolves the model's `CDestructionHolder` (`CModelConfiguration.14`) and **always returns configuration index 0** of its list, with no platform check at this call site. That is not a gap: `CDestructionHolder::Finalize(platform, name)` (read in full, `Engine.dll`) is the loader-time step that **deletes every configuration whose `EPlatform` mask (`CDestructionConfig.9`) doesn't include the running platform**, so by the time gameplay code ever calls `samGetDestructionConfig`, a two-configuration holder has already been pruned down to the one configuration for this platform (index 0 is simply "the surviving one"). This **resolves `destruction.md`'s open note** "how the engine picks between two matching configurations is not stated by the data" for the platform-mask case — Finalize is the mechanism — though it does not explain the four same-mask pairs `destruction.md` also found (e.g. two configurations both masked `0xFFFFFFFF`, differing only by name): those simply aren't filtered by `Finalize` at all, and nothing read for this task picks among same-mask survivors beyond "whichever is still first in the list". `samGetModelDestructionData(modelRenderable)` is a thin wrapper: it calls `samGetDestructionConfig` and returns that configuration's `.4` custom-data pointer (`CDestructionConfig` offset confirmed by the `AddRef`/`RemRef`/destructor pattern) only if it is non-null **and** its dynamic type actually derives from the expected data type (a defensive type check, since `.4` is stored as a generic base pointer). `CModelDestructionCustomData` itself exports no methods of its own (no decompiled class file exists for it — it is a plain data record on the empty `CDestructionData` base, which is nothing but a vtable over `CObject`); the only fields this task's code paths touch are a debris count and two further values read directly by `ExecuteDestruction` and handed to the debris-spawning helper above — consistent with `destruction.md`'s already-named `mdcd_*` members, but this task did not re-derive which of those named members those three raw reads correspond to.
