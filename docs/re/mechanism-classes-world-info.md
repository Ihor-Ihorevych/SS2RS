## Summary

**`CWorldInfoEntity`** (exactly **one per world**: 59 entities in 59 worlds, 138 named methods) is the **level's service object**: it knows the chapter chain and the current chapter, keeps the lists of living enemies, spawn slots, rides and debris, runs the **dynamic music** (relaxing, tense, fight, war), the level timer and counter, the real-time factor, the current cutscene camera, the hostility graph and the path-finding service, and starts the end-of-level sequence. **`CChapterInfoEntity`** (307 in 51 worlds, 16 named methods) is **one chapter** of a level: a **checkpoint** with the player's start loadout (health, armor, weapons, ammunition), the enemy limits, the link to the next chapter and, for the last chapter, the link to the **next level**.

What a reader needs to know first:

1. **A level is a chain of chapters.** Each chapter record links to the next (`ep_hepNextChapter`: set in 245 of 307, null in 62); the world info holds the first one (51 of 59 worlds; 8 worlds have none) and the current one. `Chapter.Start` (a script command) starts a chapter (`level-logic.md`: 249 uses): the world info resets the world to it (`ResetWorldToChapter`), and the chapter raises `Started` and, when it ends, `Finished`.
2. **A chapter carries the player's loadout.** `ep_slHealth` (100 in 200 of 307, 150 in 39, 120 in 30, 200 in 16, 130, 140, 110, 80, 50), `ep_slArmor` (0 in 148, 50 in 49, 100 in 33, 20, 30, 200, 70, 10, 60 ...), `ep_ulWeaponsAddedToPlayer` (a `WeaponFlags` set: 0 in 235, 1772 in 9, 28 in 7 ... 37 distinct), `ep_hcaiCustomAmmoItemsAddedToPlayer` (an ammunition container: 218 set), `ep_wiPreferredWeapon` (-1 in 138; 3, 5, 4, 10, 6, 7, 2, 8), `ep_fAmmoRatio` (0.25 in 151, 0.5 in 45, 0 in 44, 0.75, 0.3, 1, 0.1 ...) and `ep_bLoseWeapons` (1 in 9): what the player has after a checkpoint restore or a level start (`player-rules.md`, `weapon-classes.md`).
3. **Enemy limits.** Each chapter has three limits of enemies alive at once (`ep_ctMaxEvilSpawneesAtOnce`, `...Good...`, `...Misc...`); the default is 10,000 (no limit); the **evil** one is set in 6 chapters (30, 30, 24, 24, 20, 10). A text file `ChapterMaxes.txt` of the patches (section 4) overrides the evil limit per chapter for the story levels.
4. **The data holds the world info in four layouts** (77 members in 42 worlds, 67 in 14, 70 in 2, 76 in 1; properties 22 in 45 worlds, 19 in 14): the chapter list, the enemy lag factor and the enemy height range members occur in 43 of the 59 worlds, the others lack some of the members; a reader defaults the missing members to the constructor's values.
5. **`SBaseEntity.1`** (the chapter link of the `S` layer) is null in all 59 world info entities and in all 307 chapter infos.

**`IsSpawningAllowed(spawner)` (read, medium for the container tests, low for the lag branch: the decompiler does not show the bodies of its comparisons).** By the spawner's `ESpawneeCountLimitType` (`mechanism-classes-spawners.md` section 3): **type 2 (good):** allowed while the number of entities in the *good* occupied container is **less than the current chapter's good limit**; **type 3 (evil):** the same with the evil container and limit, **but first**, when the session's **enemy multiplier is greater than 1**, an "enemy lag" is added: `en_fEnemyLagFactor += spawner.en_fPuppetLagFactor` and the spawn is refused when the sum exceeds the chapter's limit taken from `en_aiChaptersMax[current chapter]` (the table from `ChapterMaxes.txt`) or, when absent, the chapter's evil limit (30 when the evil limit is 10,000); **type 4 (misc):** the misc container against the misc limit; type 1: always allowed; any other value logs "SWorldInfo::IsSpawningAllowed() Unknown spawnee limiting type enum found.". A spawner refused enters the **waiting list** of its type (`INeedSpawnSlot`: it logs "INeedSpawnSlot() called for an entity that is already registered..." if it was already in); `RegisterSpawnSlot` adds a spawned entity to the occupied container and `UnregisterSpawnSlot` removes it (a null entity logs "Spawner that was registered for spawn slot waiting is now NULL.") and wakes the first waiting spawner (`OnSpawnSlotAvailable`).

**The dynamic music rule (`OnStep`, read, medium).** On the host each step: when a puppet with a foe exists (`PuppetWithFoeExists`) the current music is switched to the **fight** type (2) unless it is already fight or war (3), with `en_bPuppetWithFoeExistsInLastFrame` set; when none exists the time of the last foe is kept and, **after `en_fContinuePlayAfterFight` (3 s)**, the music is crossfaded back to the **relaxing** type (0) if it was fight or war. A **war** (3) track exists only where `ep_pbsWarMusic` is set (1 world) and lasts at least `en_fMinDurationOfWarMusic` (20 s) (profiled). The volume is faded by the number of players (`GetPlayersCount`). The real-time factor is moved from its start value to `en_fDesiredRTF` over `en_fRTFFadeInTime`, then reset to -1; the **timer** compares the elapsed time with `en_fTimerDuration` and raises **`TimerFinished`** once.

### 4. Chapter enemy maxima and `ChapterMaxes.txt`

`SetChapterEnemyMaxes` (read in structure, medium; it does nothing in a deathmatch or without a game info entity): it **walks the chain of chapters** (next-chapter links), stores each chapter's name in `en_astrChapters` and a **default maximum** in `en_aiChaptersMax` (the chapter's evil limit when it is below 100, otherwise **50**), then reads the text file `Content/SeriousSam2/ChapterMaxes.txt` (if it exists), finds the section whose header equals the **world's file name** and, for each `ChapterNNN = "value"` line, **replaces the maximum of the chapter with that name**; a name that does not match logs "'...' does not match '...' in Content/SeriousSam2/ChapterMaxes.txt."; lines `MIN_ENEMY_HEIGHT` and `MAX_ENEMY_HEIGHT` set the allowed height range (`en_iMinEnemyHeight`, `en_iMaxEnemyHeight`, defaults -150 and 180); a further bound derived from the session's enemy multiplier is applied to the default (not read).

**The file** (two copies, in `Patch_02_090_593613.gro` with 573 lines and `Patch_02_100_800000.gro` with 572; the later one is used): a text file with `//` comments and **47 level sections** `"<level folder name>" { Chapter001 = "40"; ... }`. Keys: `ChapterNNN` (274 lines), `ChapterInfoNNN` (54: the chapter names of levels whose chapter info entities carry that name), a few with a suffix (`Chapter007a`, `ChapterInfo001_b`, `Chapter_001`, `Second_Wave`, `Third_Wave`, `Boss_Fight_Chapter`) and `MIN_ENEMY_HEIGHT`/`MAX_ENEMY_HEIGHT` (2 each; the value -50 and 300 occur once and twice). **Values** (quoted strings of integers): 35 in 99, 25 in 86, 40 in 75, 30 in 47, 50 in 13, 20 in 11, 45 in 10, 15 in 6, 300 in 2, 55 in 2, 10 once, -50 once. The mismatch of names inside the file (for example `Chapter08` and `Chapter10` without the leading zeros in one level) is as stored: those lines never match a chapter and are logged. The one-line differences between the two copies: one `ChapterInfo` line.

## Invariants

1. Every world has exactly one `CWorldInfoEntity` and one record (59 of 59); 51 of 59 have a first chapter; all 307 chapter infos have a record.
2. In every stored world info the timer duration and counters are -1, the current music is -1 (none), the containers are empty and `en_iCurrentChapter` is 0 (layouts that have it); the chapter's `en_bFinished` is 0 in all 307.
3. The chapter chain is acyclic (the code refuses a circular link: `AllowNextChapter`); 245 of 307 chapters have a next chapter and 62 end a chain.
4. Default limits: evil, good and misc are 10,000 in every chapter but 6 evil limits (script).
5. `ChapterMaxes.txt` has 47 level sections in both copies.
